# 多模型文档评审

调用 MCP multi-reviewer 工具，使用多个 AI 模型并行评审文档，输出聚合对比报告。

## 适用场景

-   需要多角度、交叉验证的重要文档评审
-   对 `/doc-review`（单模型）结果存疑，希望二次验证
-   需要多方意见作为修订依据

## 输入

$ARGUMENTS

格式示例：
```
/doc-review-multi /path/to/文档.md
/doc-review-multi /path/to/文档.md --focus 重点检查数据准确性
/doc-review-multi /path/to/文档.md --models gpt-4o grok-3
```

## 先决条件检查

**在执行任何步骤前，先完成以下检查：**

**参数解析**

1.  提取文件路径（第一个参数）
2.  提取 `--focus` 后的评审重点说明（可选）
3.  提取 `--models` 后的模型列表（可选，默认：gpt-4o、grok-3、gemini-2.0）
4.  **容量预检**：用 `ls -l` 获取文件大小，估算 tokens = 字节数 ÷ 3.5；计算当前已用量；已用量 + 估算 > 950K → 应用决策树（见容量管理规范），停止加载

若无文件路径参数，输出提示并中止：

> 请提供文档路径：`/doc-review-multi /path/to/文档.md`

## 执行步骤

### 1. 调用 MCP 工具

调用 MCP Server `multi-reviewer` 的 `review_document` 工具：

```json
{
  "file_path": "<绝对路径>",
  "review_focus": "<评审重点，无则省略>",
  "models": ["gpt-4o", "grok-3", "gemini-2.0"],
  "review_language": "zh"
}
```

### 2. 整理评审报告并写入文件

将 MCP 工具返回的内容整理为以下结构，写入 MD 文件：

**输出路径**：与被评审文档同目录，文件名格式：
```
{原文件名（不含扩展名）}_review@{YYYYMMDDHHmm}.md
```

**文件结构**：

```
# 评审报告：{原文档标题}

+ 评审时间：{时间}
+ 评审模型：{模型列表}
+ 被评审文件：{文件路径}

# 1 综述

+ 各模型评审的共识结论，包括：
  - 文档整体质量判断
  - 最突出的优点（跨模型共识）
  - 最需优先修订的问题（跨模型共识）

# 2 {模型A} 评审意见

+ 该模型的完整评审内容，保留原文

# 3 {模型B} 评审意见

+ 该模型的完整评审内容，保留原文

# 4 {模型C} 评审意见

+ 该模型的完整评审内容，保留原文

# 5 多模型意见汇总

+ 按议题维度对比各模型意见，格式如下：

## 5.1 {议题一}

| 维度     | {模型A} | {模型B} | {模型C} |
| -------- | ------- | ------- | ------- |
| 核心观点 | ...     | ...     | ...     |
| 严重程度 | ...     | ...     | ...     |

## 5.2 {议题二}

...（以此类推，覆盖各模型提及的所有主要议题）
```

写入完成后，在对话中输出：
```
评审报告已生成：{报告文件路径}
```

### 3. 给出后续操作建议

报告末尾提示：

```
后续操作建议：
- /doc-revise <文件路径> ：整合以上评审意见执行修订
- /doc-review <文件路径> ：使用 Claude 执行深度内部质量检查
- /doc-align             ：检查跨文档一致性
```

## 不执行

-   **不修改**文档（仅评审，不修订）
-   **不加载**规范文档（评审由各模型基于通用标准进行）
-   **不合并**各模型意见（保留各方独立观点，由用户判断采纳）

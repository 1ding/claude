# Markdown 转 PPT 内容稿

将普通 Markdown 文档按 PPT 展示逻辑重构为 PPT 内容稿（结构化 Markdown）。

## 用法

```
/convert-to-fit-ppt /path/to/源文档.md [附加指令]
```

## 输入

$ARGUMENTS

## 先决条件检查

### 参数解析

若 $ARGUMENTS 首个词为文件路径（含 `/` 或以 `.md` 结尾）：
1.  提取文件路径
2.  **容量预检**：用 `ls -l` 获取文件大小，估算 tokens = 字节数 ÷ 3.5；计算当前已用量（[LOADED *] 记录 + [CAP DELTA] chars ÷ 3.5 + 30K）；若 已用量 + 估算 > 180K 且模型名称不含 "1m" → 拒绝执行并告知用户
3.  读取源文档
4.  输出 `[LOADED target] {文件路径} | ~{tokens} tokens`
5.  路径之后的剩余内容视为附加指令

若无文件路径 → 检查会话中是否有 `[LOADED target]` 记录。均无则报错中止：

> ⚠️ 请提供源文档路径：
> ```
> /convert-to-fit-ppt /path/to/源文档.md
> ```

### 自动加载规范

加载 PPT 内容格式规范 schema（TW-FMT-PPT-01）：

```bash
ls .claude/specs/convert/schema/生成适合转换为PPT的Markdown内容指令_v*.md.schema.yaml | sort | tail -1
```

读取该文件并输出 `[LOADED spec] {路径} | ~{tokens} tokens`。

若文件不存在 → 报错中止：

> ⚠️ 未找到 PPT 内容格式规范 schema。请确认 `.claude/specs/convert/schema/` 中存在该文件。

## 执行步骤

### 1. 分析源文档

-   识别源文档的章节结构、内容特征（段落密度、数据量、代码量、表格数量）
-   估算转换后的 PPT 页数

### 2. 按规范执行内容重构

按 TW-FMT-PPT-01 规范，对源文档逐章节执行以下转换：

-   **标题层级映射**：源文档标题映射为 `#`（封面）、`##`（章节分隔页）、`###`（内容页）、`####`（子页面）
-   **内容拆分**：每个 `###` 对应一个 PPT 页，内容过多时拆分为多页
-   **段落要点化**：连续段落转为 5-8 个结构化要点，每条 20-50 字
-   **数据标注**：为核心概念添加 `[KEY]`、数据添加 `[DATA]`、适当位置添加 `[CHART:*]` 等视觉建议标注
-   **页面容量控制**：每页总字数 400-500 字（不含代码和标注）

### 3. 质量检查

按 TW-FMT-PPT-01 schema 中 quality_checks 规则验证：

-   单页检查（标题、要点数、字数、标注、嵌套层级）
-   全文检查（标题层级、章节数量、标注分布、内容密度均衡）

### 4. 输出

将转换后的 PPT 内容稿写入源文档所在目录的 `../ppt/` 目录（不存在则创建）：

-   文件名：`{源文件名}-内容稿_v0.01_R01@{时间戳}.md`
-   输出 `[CAP DELTA]` 标记

### 5. 报告

```
---转换完成---
源文档：{源文件名}
输出文件：../ppt/{内容稿文件名}
PPT 页数：{总页数}（封面 {N} + 章节页 {N} + 内容页 {N}）
标注统计：[KEY] {N} · [DATA] {N} · [CHART:*] {N} · [CODE:*] {N}
```

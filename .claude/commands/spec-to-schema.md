# 规范转Schema

将规范文档转换为精简的 YAML Schema 文件，用于 AI 编写阶段加载（替代完整规范，降低容量消耗）。

## 适用场景

-   规范文档已定稿，需要生成对应的 schema 文件
-   规范文档更新后，需要同步更新 schema
-   为新规范创建首个 schema 版本

## 不适用场景（请改用对应 skill）

-   比对 schema 与规范的一致性 → `/schema-validate`
-   修订规范文档本身 → `/doc-revise`
-   检查规范文档质量 → `/doc-review`

## 输入

$ARGUMENTS

### 参数格式

```
/spec-to-schema <规范文档路径>
```

### 参数说明

-   **规范文档路径**（必需）：待转换的规范文档路径

### 使用示例

```
/spec-to-schema .claude/specs/common/C01-内容表达规范_v0.22@202602241415.md
```

### 输出规则

-   Schema 文件自动保存到规范文档所在目录的 `../schema/` 目录
-   文件名格式：`{规范文档名}.schema.yaml`
-   示例：规范文档 `.claude/specs/common/C01-内容表达规范_v0.22@202602241415.md`
  → Schema 文件 `.claude/specs/schema/C01-内容表达规范_v0.22@202602241415.schema.yaml`

## 先决条件检查

**在执行任何步骤前，先完成以下检查：**

**参数解析（规范文档）**

若 $ARGUMENTS 提供了规范文档路径（含 `/` 或以 `.md` 结尾）：
1.  提取文件路径和可选章节参数（格式 `N` 或 `N-M`，置于路径之后）
2.  读取规范文档（有章节参数时按 `# ` 一级标题切分，只加载指定章节）
3.  输出 `[LOADED target] {文件路径} | ~{tokens} tokens`

若 $ARGUMENTS 未提供路径 → 扫描当前会话历史中的 `[LOADED *]` 记录，确认：
-   [ ] 已存在 `[LOADED target]` 或 `[LOADED spec]` 记录（规范文档已加载）

如两者均不满足，输出以下提示并**立即中止**，不执行后续任何步骤：

> ⚠️ 请提供规范文档路径：
> ```
> /spec-to-schema /path/to/规范文档.md
> /spec-to-schema /path/to/规范文档.md 3       # 只加载第3章
> /spec-to-schema /path/to/规范文档.md 1-2     # 只加载第1、2章
> ```

## 执行步骤

### 1. 确认规范文档

-   规范文档路径已在先决条件检查中确定（来自 $ARGUMENTS 或会话历史 `[LOADED target]` / `[LOADED spec]` 记录）
-   读取规范文档内容（先决条件检查中已加载时直接使用）
-   识别规范文档的类型（layout / style / domain / spec）

### 2. 提取核心约束规则

按以下原则提取规范中的核心约束：

-   **保留**：强制性规则、判断标准、格式要求、必要元素清单
-   **精简**：示例（保留关键示例，删除冗余示例）、说明性文字（提炼为简短规则描述）
-   **删除**：背景介绍、详细解释、教学性内容、重复说明

提取内容应包括：
-   文档标识信息（doc_id, doc_name）
-   核心规则分组（按规范章节结构组织）
-   每条规则的简洁表述（YAML 格式）
-   关键示例（正例/反例对照）

### 3. 生成 Schema 文件

生成 YAML 格式的 schema 文件，包含：

```yaml
# {规范名称} Schema
# 来源规范：{规范文档路径}
# 用途：AI 内容编写阶段加载此 schema（替代完整规范），提供{规范类型}约束
# 完整规则（更多示例和详细说明）：见原规范文件

doc_id: {规范编号}
doc_name: {规范名称}

# ── 规则分组1 ──
group1:
  rule: "规则描述"
  示例: "关键示例"

# ── 规则分组2 ──
group2:
  子规则1: "规则描述"
  子规则2: "规则描述"

# ... 其他规则分组
```

### 4. 保存与验证

-   确定输出路径：
    -   从规范文档路径提取目录（如 `.claude/specs/common/`）
    -   构建 schema 目录路径：`{规范文档目录}/../schema/`（如 `.claude/specs/schema/`）
    -   如 schema 目录不存在，创建该目录
    -   文件名为 `{规范文档名}.schema.yaml`
-   保存 schema 文件，立即输出 `[CAP DELTA]` 标记（见容量管理规范）
-   输出生成报告：

```
---Schema 生成报告---

规范文档：{规范文档路径}
Schema 文件：{schema 文件路径}

提取内容：
- 规则分组数：{数量}
- 核心规则数：{数量}
- 保留示例数：{数量}

建议后续操作：
- 使用 /schema-validate 验证 schema 与规范的一致性
- 在编写流程中使用 schema 替代完整规范加载
```

## 不执行

-   **不修改**原规范文档
-   **不执行**规范文档的质量检查
-   **不加载**关联文档
-   **不执行**schema 与规范的一致性验证（由 /schema-validate 负责）

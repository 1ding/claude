# 恢复中断的编写/修订任务

从计划文件恢复上次中断的编写或修订任务，跳过阶段零，自动加载所需文档。

## 触发条件

**TRIGGER when**：用户输入含以下任意模式（无需显式输入 `/doc-resume`）：
-   `按 {计划名称} 完成相关{编写/修订}`
-   `按 plans/{计划文件}.md 继续`
-   `继续 {计划名称}`
-   计划名称含 `编写计划_` 或 `修订计划_` 关键词

## 适用场景

-   上次编写/修订因容量不足中断，需要继续
-   上次会话结束时有未完成的计划文件
-   从交接文件恢复工作上下文

## 输入

$ARGUMENTS

接受以下格式：
-   `按 {计划名称} 完成相关{编写/修订}`（推荐，简洁格式）
-   `按 plans/{计划文件名}.md 继续`（完整路径格式）
-   直接输入计划文件路径（如 `plans/修订计划_05-详细需求.md`）

计划名称为文件名去掉路径和 `.md` 扩展名，如 `修订计划_05-详细需求`。

## 先决条件检查

**在执行任何步骤前，先完成以下检查：**

从 $ARGUMENTS 中提取计划名称或路径：

-   若含完整路径 → 直接使用
-   若含计划名称（含 `编写计划_` 或 `修订计划_` 关键词）→ 在 `projects/` 下各项目的 `plans/` 目录中搜索对应文件
-   若均不满足，输出以下提示并**立即中止**：

> ⚠️ 请指定计划名称或路径，例如：
> ```
> 按 修订计划_05-详细需求 完成相关修订
> 按 编写计划_03-领域设计 完成相关编写
> ```

## 执行步骤

### 1. 读取计划文件

-   读取计划文件
-   识别任务类型：编写 or 修订
-   提取进度信息：已完成项、剩余项、当前批次、断点位置
-   提取 `## 需加载文档` 中的文档列表

### 2. 读取交接文件（如有）

-   检查 `plans/` 下是否存在对应的交接文件（`plans/交接_{文档名}_*.md`）
-   如有，读取交接文件获取：决策记录、开放问题、生效假设、断点位置

### 3. 自动加载文档

按计划文件 `## 需加载文档` 表中列出的所有文档自动加载（`.claude/rules/version-management.md` 由 Claude Code 自动加载，无需重复读取）：

| 加载项                                       | 条件                                     |
| -------------------------------------------- | ---------------------------------------- |
| drafts/ 中的工作文档（计划中记录的最新版本） | 始终加载                                 |
| decisions.md                                 | 始终加载（从目标文档路径推断项目目录）   |
| `## 需加载文档` 表中的全部文档               | 始终加载（自动执行，无需用户手动加载）   |
| `.claude/rules-ext/capacity-management.md`   | 始终加载                                 |
| `.claude/rules-ext/structure-constraints.md` | 始终加载                                 |
| `.claude/rules-ext/quality-checklist.md`     | 仅最后一批或汇总阶段加载                 |

> 提示：如在执行 /doc-resume 前已通过 /load-* 加载了相关文档，直接使用会话中已有内容，无需重复加载。

### 4. 输出恢复确认并继续执行

输出简要确认后，**无需等待用户响应，立即开始执行**：

```
---恢复确认---
计划文件：{文件名}
任务类型：{编写/修订}
总进度：已完成 M/N 项（第 X 批 / 共 Y 批）
断点：{从计划文件读取}

已加载：
- 工作文档：{路径}
- {其他已加载文档列表}

即将执行第 X+1 批：{内容描述}
---
```

### 5. 继续执行

-   按 `/doc-write` 或 `/doc-revise` 定义的批次流程继续执行
-   遵循计划文件中记录的基准变更（硬约束）和交接文件中的决策记录（如有）
-   每批完成后更新计划文件（状态 + `## 下次会话` 断点）
-   任务全部完成后（阶段二完成），执行计划文件与大纲文件清理（参见 `/doc-write` 或 `/doc-revise` 步骤5）

## 与 /doc-write、/doc-revise 的关系

-   `/doc-write` 和 `/doc-revise` 专注于**新建模式**（从阶段零开始）
-   `/doc-resume` 专注于**恢复模式**（跳过阶段零，从断点继续）
-   恢复模式下不重复执行输入识别、内部准备、方案确认等阶段零步骤

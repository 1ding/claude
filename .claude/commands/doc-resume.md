# 恢复中断的编写/修订任务

从交接文件恢复上次中断的编写或修订任务，跳过阶段零，自动加载所需文档。

## 触发条件

**TRIGGER when**：用户输入含以下任意模式（无需显式输入 `/doc-resume`）：
-   `按 {交接文件名} 继续`
-   `按 plans/{交接文件}.md 继续`
-   `继续 {交接文件名}`
-   文件名含 `交接_` 关键词

## 适用场景

-   上次编写/修订因容量不足中断，在新会话继续

## 输入

$ARGUMENTS

接受以下格式：
-   `按 {交接文件名} 继续`（推荐，简洁格式）
-   `按 plans/{交接文件名}.md 继续`（完整路径格式）
-   直接输入交接文件路径（如 `plans/交接_05-详细需求_202603041230.md`）

交接文件名为文件名去掉路径和 `.md` 扩展名，如 `交接_05-详细需求_202603041230`。

## 先决条件检查

**在执行任何步骤前，先完成以下检查：**

从 $ARGUMENTS 中提取交接文件名称或路径：

-   若含完整路径 → 直接使用
-   若含 `交接_` 关键词 → 在 `projects/` 下各项目的 `plans/` 目录中搜索对应文件
-   若均不满足，输出以下提示并**立即中止**：

> ⚠️ 请指定交接文件名称或路径，例如：
> ```
> 按 交接_05-详细需求_202603041230 继续
> ```

## 执行步骤

### 1. 读取交接文件

-   读取交接文件
-   提取：断点位置、剩余任务、决策记录、开放问题、生效假设
-   提取 `## 需加载文档` 中的文档列表

### 2. 自动加载文档

按交接文件 `## 需加载文档` 中列出的所有文档自动加载（`.claude/rules/version-management.md` 由 Claude Code 自动加载，无需重复读取）：

| 加载项                                       | 条件                                     |
| -------------------------------------------- | ---------------------------------------- |
| drafts/ 中的工作文档（交接文件中记录的最新版本） | 始终加载                              |
| decisions.md                                 | 始终加载（从目标文档路径推断项目目录）   |
| `## 需加载文档` 中的全部文档                 | 始终加载（自动执行，无需用户手动加载）   |
| `.claude/rules-ext/structure-constraints.md` | 始终加载                                 |
| `.claude/rules-ext/quality-checklist.md`     | 仅汇总阶段加载                           |

> 提示：如在执行 /doc-resume 前已通过 /load-* 加载了相关文档，直接使用会话中已有内容，无需重复加载。

### 3. 输出恢复确认并继续执行

输出简要确认后，**无需等待用户响应，立即开始执行**：

```
---恢复确认---
交接文件：{文件名}
断点：{从交接文件读取}

已加载：
- 工作文档：{路径}
- {其他已加载文档列表}

即将继续：{剩余任务描述}
---
```

### 4. 继续执行

-   按 `/doc-write` 或 `/doc-revise` 定义的流程继续执行
-   遵循交接文件中记录的决策记录和生效假设
-   任务完成后（阶段二完成），删除 `plans/交接_{文档名}_*.md`；如使用了大纲文件，同步删除 `plans/大纲_{文档名}.md`

## 与 /doc-write、/doc-revise 的关系

-   `/doc-write` 和 `/doc-revise` 专注于**新建模式**（从阶段零开始）
-   `/doc-resume` 专注于**恢复模式**（跳过阶段零，从断点继续）
-   恢复模式下不重复执行输入识别、内部准备、方案确认等阶段零步骤

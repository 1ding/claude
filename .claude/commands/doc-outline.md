# 生成文档大纲

生成文档大纲。

## 适用场景

-   为新文档生成大纲
-   更新已有文档的大纲结构

## 输入

$ARGUMENTS

## 先决条件检查

**在执行任何步骤前，先完成以下检查：**

**参数解析（目标文档，可选）**

若 $ARGUMENTS 首个词为文件路径（含 `/` 或以 `.md` 结尾）：
1.  提取文件路径和可选章节参数（格式 `N` 或 `N-M`，置于路径之后）
2.  **容量预检**：用 `ls -l` 获取文件大小，估算 tokens = 字节数 ÷ 3.5；计算当前已用量（[LOADED *] 记录 + [CAP DELTA] chars ÷ 3.5 + 50K）；若 已用量 + 估算 > 950K → 应用决策树（见容量管理规范），停止加载
3.  读取目标文件（有章节参数时按 `# ` 一级标题切分，只加载指定章节）
4.  输出 `[LOADED target] {文件路径} | ~{tokens} tokens`
5.  将路径及章节参数之后的剩余内容视为本命令的大纲生成指令输入

扫描当前会话历史中的 `[LOADED *]` 记录：
- 若会话历史中**无任何** `[LOADED *]` 记录，且 $ARGUMENTS 无文件路径 → 视为全新大纲，允许继续（用户输入驱动）
- 若存在 `[LOADED *]` 记录但**无** `[LOADED target]`、`[LOADED outline]`、`[LOADED upstream]` 任一 → 提示后继续

无需强制中止，但若用户已有文档想基于它生成大纲，可直接传入路径参数或先执行 `/load-target`：
```
/doc-outline /path/to/已有文档
/doc-outline /path/to/已有文档 3       # 只加载第3章
/doc-outline /path/to/已有文档 1-2     # 只加载第1、2章
```

## 执行步骤

### 1. 确认输入来源

从会话历史扫描 `[LOADED *]` 记录，整理可用输入：
- 已有文档（`[LOADED target]`）：用于更新大纲结构
- 规范文档（`[LOADED spec]`、`[LOADED domain]`）：用于约束大纲结构
- 上游文档（`[LOADED upstream]`）：用于把握上下文和范围

读取 `projects/{项目}/decisions.md`（若能从已加载文件路径推断项目目录则读取，否则跳过）。

### 2. 执行大纲生成流程

按以下阶段执行：

-   阶段零：会话初始化（输入识别、内部准备、输入评估与确认）
-   阶段一：大纲生成（模板驱动或自主生成）
-   大纲输出与确认

### 3. 输出

大纲文件写入 `projects/{项目}/plans/大纲_{目标文档名}.md`，写入后立即输出 `[CAP DELTA]` 标记（见容量管理规范）。

## 不执行

-   **不自动加载**规范文档或关联文档（由用户通过 /load-* 自行决定）

# 1 总则

+   **文档编号**：C01
+   **文档名称**：内容表达规范
+   **文档密级**：【内部资料】 -- 不主动对外公开。
+   **适用范围**：所有类型文档的内容编写
+   **适用对象**：天帷文档编写者、文档审核者
+   **管理要点**：本规范为天帷通用基础规范，与 C02、C11、C99 配套使用；修订需经评审后更新。
+   **关联规范**：C02 排版格式规范、C11 文档通用结构规范、C99 天帷通用术语规范

# 2 知识单点定义原则

+   每个知识点只在一个位置完整定义，其他位置通过精确引用指向。

+   **冗余判断**：删掉某段话后知识点仍有完整定义 → 冗余，应改为引用。

+   **引用格式**：使用"见 X.X 节"或"按 X.X 节定义"。

# 3 术语处理

## 3.1 术语三层分类

-   **业界通用术语**：AI 已理解，附录仅列名称，无需定义。
-   **天帷通用术语**：引用 C99，附录列名称和来源，不重复定义。
-   **文档专有术语**：在附录中完整定义。

+   **判定顺序**：业界通用? → 天帷通用? → 文档专有。

## 3.2 正文术语使用

+   含义偏离常见用法的术语，首次出现时内联定义。

-   正例：业务活动（即 PL2 流程节点）
-   反例：业务活动

# 4 逻辑性与段落结构

## 4.1 篇幅控制

+   单章不超过 1 万汉字（约 16K tokens）。超过时拆分为多个一级标题。

## 4.2 段落聚焦

+   一段一判断。出现"但是/另外/同时还需要注意"时，应拆分为独立段落。

## 4.3 信息层次

+   先前提，后细节：先给出总体原则或分类框架，再逐项展开。

## 4.4 分类完备性（MECE）

+   同一分类维度的各类别不交叉、合起来穷尽。

## 4.5 因果显式标注

+   A 是 B 的原因时，用"因此"或"→"显式标注，不隐含因果关系。

## 4.6 递进方向一致

+   按严格程度连续排列（必须 → 推荐 → 允许），不交叉穿插。

## 4.7 并列条目一致性

+   并列条目按统一维度分组，不混杂排列。

## 4.8 规则聚合

+   同一对象的规则按维度聚合为自包含的规则组，避免分散。

## 4.9 规则组展开顺序

+   规则组内的展开顺序：规则要求 → 示例（可选）→ 补充说明（可选）。

# 5 表格与列表选择

+   默认优先使用列表。

-   用表格：需同时对齐 ≥ 3 个字段进行多维度对比。
-   用列表：单纯映射、正反例对照、枚举项说明。
-   短表格（≤ 4 行）：可保留表格。
-   长表格（≥ 5 行）：优先改写为列表。

# 6 图的使用

## 6.1 使用条件

+   去掉图后读者会理解错要素关系 → 用图；不会 → 用文字或表格。

## 6.2 图的自包含性

+   图中标注应足够完整，无需阅读正文即可理解核心含义。

## 6.3 正文文字自足性

+   正文文字确保不看图也能完整理解。图是可视化增强，不是信息的唯一载体。

## 6.4 图的归属

-   **留正文**：必要视图（要素关联、核心流程、架构）。
-   **归附录**：辅助视图（方法论推导、概念教学）。

# 7 语言精简

## 7.1 具体化

-   用数据代替修饰词。
    -   正例：处理速度为 X ms/batch
    -   反例：非常高效地处理
-   名词具体，不抽象。
    -   正例：对 embedding 向量做 L2 归一化
    -   反例：对相关数据进行处理

## 7.2 精简化

-   砍万能动词包装。
    -   正例：清洗数据
    -   反例：对数据进行清洗
-   砍正确的废话。
    -   正例：使用前配置 API Key
    -   反例：在使用之前，需要先进行相关的配置工作
-   控制"的"字链，单句中"的"字不超过 2 个。

## 7.3 清晰化

-   否定句改肯定句。
    -   正例：先完成初始化，再调用
    -   反例：不要在未完成初始化的情况下调用

# 8 语言风格

-   使用陈述句，避免感叹句。
-   主动语态、短句优先，警惕长定语从句嵌套。
-   一个概念全文只用一个术语，不在同义词间交替。
-   避免口语化、主观性或情感化表达。

# 9 规范性用语

-   **应**：强制要求
-   **宜**：推荐做法
-   **可**：允许的选项
-   **不应**：强制禁止
-   **不宜**：不推荐

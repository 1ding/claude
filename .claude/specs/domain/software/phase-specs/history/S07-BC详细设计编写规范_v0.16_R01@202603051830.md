# 3 正文章节结构

+   本章规定BC详细设计文档正文各章（第1章至第13章）的编写规范，包括各章的输出结构、子节定义、粒度标准、约束与规则及典型示例。

## 3.1 第1章 总则

### 3.1.1 章节结构

+   总则为文档元数据声明章节，无下级章节，全部内容以列表形式呈现，篇幅控制在半页以内。

| 元数据项 | 格式说明                                                                   |
| -------- | -------------------------------------------------------------------------- |
| 文档编号 | {BC编号}-{设计单元编号}，如 BC11-SD01                                      |
| 文档名称 | {BC名称} {设计单元名称}详细设计，如"租户管理BC 租户生命周期子领域详细设计" |
| 目的     | 一句话描述，如"规定租户生命周期子领域的详细设计"                           |
| 范围     | 本设计单元的边界声明（引用第2章前置背景中业务边界的概要）                  |
| 管理要点 | 关键词列表，如"P1版本展开、三表模型、五件套接口"                           |
| 文档密级 | 固定填写：【商密二级】 -- 外发必追责                                       |

**表 总则元数据项说明**

+   补充说明
    -   文档编号应与BC总体设计中的设计单元编号一致
    -   管理要点应提取当前版本展开情况和本文档的核心结构特征，3-6个关键词
    -   文档密级固定为商密二级，不可自行调整

## 3.2 第2章 背景与约束

+   第2章采用两段式结构：2.1"前置背景"收录设计单元的身份定位、交付规划、能力边界及上游约束，为需求落位提供完整的输入上下文；2.2"需求落位"在前置背景基础上，对本设计单元承接的S05需求逐条确定处置方式，是S05与后续各设计章节之间的追溯基线。
+   设计决策（状态机、并发策略、幂等策略）属于本规范内部的设计产出，不在本章定义：状态机在第4章各聚合设计中定义；并发与幂等设计在第4章（乐观锁）和第6章（接口幂等性）中定义。

### 3.2.1 章节结构

| 小节               | 输出形式   | 说明                                                                     |
| ------------------ | ---------- | ------------------------------------------------------------------------ |
| 2.1 前置背景       | （见子节） | 五类输入上下文，共同构成需求落位的背景；不在此处作设计决策               |
| 2.1.1 设计单元定位 | 定义表     | 键值对表格，每行一个定位属性；大BC附子领域依赖关系说明                   |
| 2.1.2 版本范围     | 版本清单表 | 每行一个版本，标注核心交付内容和状态；对应需求落位中各需求的版本归属     |
| 2.1.3 业务边界     | 双清单表   | "范围内"和"范围外"各一张表；范围外内容是需求落位中废弃条目的主要依据     |
| 2.1.4 架构约束引用 | 约束引用表 | 引用BC总体设计（或系统设计）中的架构决策，不重复定义                     |
| 2.1.5 安全合规约束 | 安全约束表 | 引用BC总体设计安全设计和外部合规要求，补充本设计单元细节                 |
| 2.2 需求落位       | 落位表     | S05需求在本设计单元的权威基线；综合前置背景，逐条确定继承/细化/废弃/新增 |

**表 第2章各小节输出形式**

+   补充说明：约束与规则

    -   设计单元定位中的所属BC、子领域编号/名称应与BC总体设计文档中的定义完全一致，不得自行新增或修改
    -   大BC应在定位表后补充一段文字，说明本子领域与其他子领域的依赖关系（依赖方向、依赖内容）
    -   小BC应在子领域编号字段标注"本文档覆盖整个BC，无子领域划分"，并引用BC总体设计中的判定依据
    -   架构约束引用表应以引用为主，不重复BC总体设计已定义的内容；如BC总体设计仅给出概要，本章应补充完整细节
    -   需求落位表须完整覆盖BC总体设计归属本设计单元的所有S05需求，是S05与S07之间的追溯基线，细节规则见3.2.3节
    -   状态机是领域设计的核心产出，统一在第4章对应聚合的设计中定义；若设计单元涉及多个聚合，各聚合状态机分别在第4章各聚合小节中定义，状态机图和转换规则表随聚合设计呈现，不在第2章集中展示
    -   并发与幂等策略为实现设计，不在本章定义：乐观锁方案在第4章各聚合根设计中说明（在聚合的属性清单或业务规则中注明 version 字段及乐观锁语义）；接口幂等性设计在第6章各接口设计中说明；长流程并发控制在第3章业务流程设计或第4章相关聚合设计中说明

+   补充说明：粒度标准

    +   本章内容属于背景上下文定义，粒度控制原则：
        -   定位表：每行一个属性，值字段简明扼要，核心关注问题2~5条
        -   版本范围：每版本一行，未来版本不展开详细内容
        -   业务边界：各张表控制在5~10行，边界模糊时优先明确"范围外"
        -   需求落位：S05归属本设计单元的所有需求必须出现，不得无声省略

## 3.3 第3章 业务设计

+   第3章"业务设计"规定BC详细设计中全部业务能力的设计方式。业务能力按是否涉及聚合根状态跃迁分为两类：

#### 3.3.2.2 业务流程标准结构（四件套）

+   每个业务流程节按以下四部分依次编写：

+   **① 流程概述**

-   **触发条件：** 何种事件或操作触发该流程
-   **结束条件：** 流程正常结束的标志

+   **② 流程图**

+   流程图使用ASCII图绘制，遵循《C02-排版格式规范》的图块规范。图示工具视目的选择（详见总分图设计原则）。未来版本的流程仅保留概述和总图，不展开流程步骤和异常处理。

+   步骤表列定义如下：

| 列名         | 说明                                                                                |
| ------------ | ----------------------------------------------------------------------------------- |
| 步骤号       | 顺序编号（1、2、3…），分支用1a/1b表示                                               |
| 步骤名称     | 简短动宾结构（如"校验租户信息"）                                                    |

| 输出         | 该步骤的输出数据或状态变更                                                          |
| 业务规则引用 | 引用领域模型中的规则编号（如TN-R-04），无则填"-"；不得重复规则内容，完整定义在第4章 |

+   异常处理是流程设计的核心价值——正常流程通常直观，关键价值在于明确各类异常场景下的系统行为。
+   异常处理表列定义如下：

| 列名     | 说明                                                  |
| -------- | ----------------------------------------------------- |
| 异常场景 | 异常的触发条件描述                                    |
| 检测时机 | 在哪个步骤检测到该异常（引用步骤号）                  |

**表 异常处理表列定义**

| 异常场景         | 检测时机 | 处理策略                      | 补偿操作         | 最终状态     |

| 必填参数为空     | 步骤1    | 拒绝操作，返回E-400001        | -                | 无变化       |
| 状态非法转换     | 步骤2    | 拒绝操作，返回E-422001        | -                | 无变化       |
| 数据库写入失败   | 步骤6    | 事务回滚，返回500，发送告警   | 回滚状态变更     | 变更前状态   |

+   每个业务操作节按以下三部分依次编写：

+   **① 功能描述**

+   功能描述为一段列表，包含以下要素：

### 3.4.3 粒度标准

+   聚合边界判断标准：

| 判断维度   | 应归入同一聚合           | 应拆分为独立聚合 |
| ---------- | ------------------------ | ---------------- |
| 事务一致性 | 必须在同一事务中保持一致 | 可接受最终一致性 |
| 生命周期   | 与聚合根同生同灭         | 有独立的生命周期 |
| 变更频率   | 与聚合根同频变更         | 变更频率显著不同 |
| 访问模式   | 总是与聚合根一起加载     | 经常独立访问     |

**表 聚合边界判断标准**

-   **业务规则粒度：** 一条规则对应一个可独立验证的业务约束；如果一条规则包含"且/或"连接的多个独立条件，应拆分为多条规则
    -   **不合理的粗粒度**："创建时所有字段校验通过"（一条规则覆盖多个独立约束）
    -   **合理的细粒度拆分**：RS-R-01"名称不可为空且不超过100字"、RS-R-02"URL格式必须合法"、RS-R-03"名称在同类型下唯一"——每条规则独立触发、独立违反、独立返回错误码
-   **领域服务判断标准：** 业务逻辑不自然归属于任何一个聚合根时 → 领域服务；业务逻辑仅涉及单个聚合内部 → 聚合根方法

### 3.4.4 约束与规则

+   聚合设计应遵循五原则：

| 原则  | 名称           | 要求                                             |
| ----- | -------------- | ------------------------------------------------ |
| 原则1 | 业务不变性约束 | 聚合内对象共同维护一个业务不变性                 |
| 原则2 | 完整的业务概念 | 聚合代表一个完整的业务概念                       |
| 原则3 | 尽量小         | 只包含核心逻辑，实体数不超过5、值对象数不超过10  |
| 原则4 | ID引用其他聚合 | 跨聚合通过ID引用，禁止直接对象引用               |
| 原则5 | 边界不跨微服务 | 聚合内所有对象属于同一BC、同一微服务、同一数据库 |

**表 聚合设计五原则**

+   副作用隔离策略——领域层应保持纯净，不直接执行I/O操作：

| 副作用类型   | 领域层 | 应用层 | 基础设施层 |
| ------------ | ------ | ------ | ---------- |
| 数据库读写   | 禁止   | 协调   | 实现       |
| 外部服务调用 | 禁止   | 协调   | 实现       |
| 消息发送     | 禁止   | 协调   | 实现       |
| 缓存操作     | 禁止   | 协调   | 实现       |
| 领域事件收集 | 允许   | 收集   | 发布       |
| 业务计算     | 允许   | -      | -          |

**表 副作用隔离策略**

+   其他规则：
-   业务方法涉及跨聚合校验或外部依赖时，在业务方法表备注中注明"需应用层协调"
-   业务规则编号全BC唯一，各设计单元使用不同前缀
-   类名和属性名遵循BC总体设计附录B的编码规范
-   领域事件命名禁止使用过于泛化的名称
-   每个事件必须包含基础字段：eventId、eventVersion、occurredOn、aggregateId、aggregateType

-   系统注入字段（如operatorId、tenantId）在约束列标注"系统注入"，表示从安全上下文自动获取，前端不传入
-   本章不写Java接口代码或类代码，仅通过表格定义契约
-   每个应用服务方法应可追溯到第2章需求落位中的需求编号或第3章流程设计中的流程步骤

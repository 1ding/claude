# 1 总则

+   **文档编号**：TW-FMT-PPT-01
+   **文档名称**：Markdown 转 PPT 内容格式规范
+   **文档密级**：【内部资料】 -- 不主动对外公开。
+   **适用对象**：AI 文档转换助手
+   **管理要点**：本规范定义将 Markdown 文档转换为 PPT 内容稿时的格式约束，包括标题层级映射、页面容量、标注系统、内容转换、代码处理等规则。

## 1.1 执行原则

-   **保持逻辑结构**：不改变原文档的章节顺序和核心观点。
-   **保持内容完整性**：不忽略、跳过或删减原文档的内容和要点；单页内容过多时分页展示。
-   **控制页面容量**：每页内容适合一个 PPT 页展示。
-   **优化表达方式**：段落文字转换为结构化要点，精简冗余表述。
-   **提供可视化建议**：以标注形式提供 PPT 可视化建议。

# 2 标题层级规则

## 2.1 层级映射

+   PPT 内容稿的标题层级与 PPT 页面的对应关系如下表所示。

    | 层级     | 语法   | PPT 用途   | 数量   | 说明                                  |
    | -------- | ------ | ---------- | ------ | ------------------------------------- |
    | 文档标题 | `#`    | 封面页     | 1 个   | 包含标题、副标题、日期                |
    | 章节标题 | `##`   | 章节分隔页 | 3-6个  | 大章节的起始页，仅标题                |
    | 主页面   | `###`  | 标准内容页 | 不限   | 每个 `###` 独立成页                   |
    | 子页面   | `####` | 主题细分   | 可选   | 从属于 `###`，标题显示为"主题/子主题" |

## 2.2 约束

-   最多使用 4 级标题（`#` 至 `####`），不应使用 `#####` 及以下。
-   子页面（`####`）标题显示格式为"父主题/子主题"。

# 3 页面容量规则

## 3.1 容量标准

+   每个 PPT 页面的内容元素应符合以下限制。

    | 元素       | 限制       | 说明                   |
    | ---------- | ---------- | ---------------------- |
    | 页面标题   | ≤20 字     | 清晰、可独立理解       |
    | 要点数量   | 5-8 条     | 最少 3 条，最多 10 条  |
    | 单条要点   | 20-50 字   | 完整表达，保持精炼     |
    | 页面总字数 | 400-500 字 | 不含代码和标注         |
    | 代码行数   | ≤50 行     | 单块代码的限制         |
    | 列表嵌套   | ≤3 层      | 主要点→次要点→细节点   |

## 3.2 字数计算

+   页面字数 = 标题字数 + 所有要点字数 + 补充说明字数。
+   不计入：代码块、标注标签、分隔符。

## 3.3 内容密度参考

-   **高密度页**（450-500 字）：概念深入解释、复杂流程说明、多维度分析
-   **标准密度页**（400-450 字）：框架介绍、方法论说明、实施步骤
-   **中密度页**（350-400 字）：要点列举、对比分析、案例说明
-   **低密度页**（300-350 字）：数据展示为主、简单流程、关键结论
-   **极简页**（<300 字）：章节封面、引用金句、单一图表

# 4 标注系统

## 4.1 核心内容标注

+   用于标记页面中的重点信息类型。

    | 标注      | 用途         | 适用场景               |
    | --------- | ------------ | ---------------------- |
    | `[KEY]`   | 核心信息强调 | 关键结论、重要概念     |
    | `[DATA]`  | 数据突出     | 统计数据、百分比、指标 |
    | `[QUOTE]` | 引用         | 权威观点、文献引用     |
    | `[CASE]`  | 实际案例     | 真实案例、应用场景     |
    | `[VS]`    | 对比说明     | 前后对比、优劣对比     |

## 4.2 视觉元素标注

+   用于建议 PPT 中应使用的图表或图片类型。

    | 标注                 | 用途     | 适用场景           |
    | -------------------- | -------- | ------------------ |
    | `[CHART:bar]`        | 柱状图   | 对比数据、排名     |
    | `[CHART:line]`       | 折线图   | 趋势变化、时间序列 |
    | `[CHART:pie]`        | 饼图     | 占比分布、构成     |
    | `[CHART:flow]`       | 流程图   | 步骤、流程、关系   |
    | `[CHART:compare]`    | 对比图   | 方案对比、优缺点   |
    | `[CHART:table]`      | 表格     | 规范数据、矩阵     |
    | `[CHART:timeline]`   | 时间线   | 发展历程、路线图   |
    | `[IMAGE:photo]`      | 实景图片 | 现场照片、产品图   |
    | `[IMAGE:diagram]`    | 示意图   | 架构图、模型图     |
    | `[IMAGE:screenshot]` | 截图     | 界面、操作示例     |
    | `[ICON:类型]`        | 图标建议 | shield/chart/user  |

## 4.3 布局标注

+   用于建议 PPT 页面的排版布局方式。

    | 标注                  | 用途     | 效果                   |
    | --------------------- | -------- | ---------------------- |
    | `[LAYOUT:left-right]` | 左右分栏 | 对比内容、代码与说明   |
    | `[LAYOUT:top-bottom]` | 上下布局 | 原理与应用、问题与方案 |
    | `[LAYOUT:center]`     | 居中突出 | 核心数据、关键结论     |
    | `[EMPHASIS:number]`   | 大号数字 | 关键指标、统计结果     |
    | `[PROGRESS:比例]`     | 进度展示 | 完成度、达成率         |

## 4.4 代码标注

+   用于指定代码块在 PPT 中的展示方式。

    | 标注             | 用途       | 说明               |
    | ---------------- | ---------- | ------------------ |
    | `[CODE:single]`  | 单栏代码   | ≤15 行，完整展示   |
    | `[CODE:double]`  | 双栏代码   | 16-30 行，左右分栏 |
    | `[CODE:compare]` | 代码对比   | Before/After 对比  |
    | `[CMD]`          | 命令行示例 | Shell 命令         |
    | `[CONFIG]`       | 配置文件   | YAML/JSON/XML 配置 |
    | `[PSEUDO]`       | 伪代码     | 逻辑说明、算法描述 |

# 5 内容转换规则

## 5.1 段落文字

+   将连续段落拆解为 5-8 个结构化要点。
+   每条要点 20-50 字，使用加粗关键词引导。
+   为核心概念添加 `[KEY]`、数据添加 `[DATA]` 标注。

## 5.2 长列表

+   按逻辑维度分组（如"组织与流程维度""管理与监督维度"），每组 3-4 条。
+   每条要点补充具体说明，不应仅列名称。

## 5.3 复杂句

+   一句话拆成多个要点，每个要点聚焦一个信息单元。

## 5.4 数据处理

+   数据可视化决策规则如下：

-   单个关键数字 → `[DATA]` + `[EMPHASIS:number]`
-   时间序列数据 → `[CHART:line]`
-   分类对比数据 → `[CHART:bar]`
-   占比构成数据 → `[CHART:pie]`
-   多维度数据 → `[CHART:table]`
-   流程步骤 → `[CHART:flow]`

# 6 代码块处理

## 6.1 基本要求

-   总行数 ≤50 行，单行长度 ≤80 字符。
-   应指定语言标签（`python`、`yaml`、`bash` 等）。
-   应添加注释说明核心逻辑。

## 6.2 代码标注选择

-   ≤15 行 → `[CODE:single]`
-   16-30 行 → `[CODE:double]`（左右分栏）
-   对比展示 → `[CODE:compare]`（Before/After）
-   配置文件 → `[CONFIG]`
-   命令行 → `[CMD]`

# 7 特殊场景处理

## 7.1 大量表格

-   简单表格（2-3 列）→ 转换为要点列举。
-   复杂表格（4 列以上）→ 标注 `[CHART:table]`。
-   对比表格 → 标注 `[CHART:compare]`。

## 7.2 大量代码

-   每个代码块 ≤50 行。
-   保留核心逻辑代码，移除辅助性代码。
-   根据行数选择对应代码标注。

## 7.3 概念密集

-   每页不超过 3-4 个核心概念。
-   核心概念标注 `[KEY]`。
-   复杂概念补充类比或例子。
-   必要时拆分为多页。

## 7.4 数据丰富

-   所有关键数据标注 `[DATA]`。
-   核心指标标注 `[EMPHASIS:number]`。
-   根据数据特点选择图表类型（见第 5.4 节）。

# 8 禁止事项

## 8.1 格式禁止

-   单页不应超过 500 字。
-   不应出现超过 3 行的连续段落文字。
-   单句不应超过 50 字。
-   代码块不应超过 50 行。
-   不应使用 Markdown 表格作为 PPT 内容（应标注 `[CHART:table]`）。
-   标题不应超过 4 级。
-   单页要点不应超过 10 条。
-   列表嵌套不应超过 3 层。

## 8.2 内容禁止

-   不应忽略或跳过原文档中的任何章节或要点。
-   不应因字数限制删除原文档的关键信息；内容过多时应分页展示。
-   不应将多个不同主题的内容合并到一页。
-   不应使用模糊表述（"可能""大概""一些"）。
-   不应出现重复内容（标题与要点重复、页面之间重复）。

## 8.3 标注禁止

-   不应滥用标注（不应每条都标 `[KEY]`）。
-   不应标注不准确（普通内容不应标 `[DATA]`）。
-   关键数据不应缺少标注。

# 9 质量检查规则

## 9.1 单页检查

+   每页提交前，逐项核对以下清单。

-   □ 标题清晰且 ≤20 字
-   □ 要点数量 5-8 条（最少 3 条，最多 10 条）
-   □ 每条要点 20-50 字，表达完整
-   □ 总字数 400-500 字（不含代码）
-   □ 添加了适当的标注（KEY/DATA/CHART 等）
-   □ 代码块 ≤50 行且有充分注释
-   □ 无 Markdown 表格
-   □ 无连续段落文字（>3 行）
-   □ 无过长单句（>50 字）
-   □ 视觉元素标注明确
-   □ 列表嵌套 ≤3 层

## 9.2 全文检查

+   结构层面：

-   □ 有且仅有 1 个文档标题（`#`）
-   □ 章节数量合理（通常 3-6 个 `##`）
-   □ 每章内容页 ≥3 页
-   □ 标题层级不超过 4 级
-   □ 逻辑连贯，章节过渡自然
-   □ 同级标题字数相近、格式统一

+   内容层面：

-   □ 每页都有明确的核心观点
-   □ 重点内容有 `[KEY]` 标注（每章至少 2-3 处）
-   □ 数据信息有 `[DATA]` 标注（有数据的地方必标）
-   □ 至少 60% 的页面有视觉元素建议
-   □ 代码示例有实际价值且注释充分
-   □ 无重复内容（标题与正文、页面之间）
-   □ 专业术语有适当解释或上下文

+   视觉层面：

-   □ 页面密度均衡（避免某些页过密或过疏）
-   □ 图表类型选择合理（符合数据特征）
-   □ 布局标注使用得当（双栏、居中等）
-   □ 关键数据使用 `[EMPHASIS:number]`
-   □ 对比内容使用 `[VS]` 或 `[CHART:compare]`
-   □ 流程性内容使用 `[CHART:flow]`
-   □ 每 2-3 页至少有 1 个视觉化标注

## 9.3 专项检查

+   代码质量检查：

-   □ 代码逻辑正确或合理
-   □ 有充分的注释说明（关键行、逻辑块、参数）
-   □ 格式规范（缩进、命名、空行）
-   □ 示例简洁且有代表性
-   □ 标注了 `[CODE:single/double]` 或其他代码标注
-   □ 单行长度 ≤80 字符
-   □ 总行数 ≤50 行

+   数据准确性检查：

-   □ 数据有来源说明或合理性
-   □ 百分比总和为 100%（如适用）
-   □ 趋势描述与数据一致
-   □ 对比数据有明确基准
-   □ 数字单位统一且明确
-   □ 关键数据都有 `[DATA]` 标注

+   标注完整性检查：

-   □ 核心概念标注 `[KEY]`（每章 2-4 个）
-   □ 所有数字标注 `[DATA]`
-   □ 建议了合适的图表类型
-   □ 复杂流程标注 `[CHART:flow]`
-   □ 对比内容标注 `[VS]` 或 `[CHART:compare]`
-   □ 大号展示的数据标注 `[EMPHASIS:number]`
-   □ 代码标注 `[CODE]` 系列
-   □ 布局需求标注 `[LAYOUT]` 系列

## A.5 完整转换示例

+   以下展示约 300 字原文转换为约 450 字 PPT 内容稿的完整过程。

+   原文：

    ```text
    数字安全治理是企业信息安全管理的核心环节，它通过建立系统化的组织架构、
    明确的职责分工、规范的流程制度和有效的监督机制，确保企业的信息安全策略
    能够有效落地执行。治理的核心在于从战略高度把握安全工作的方向，而不是
    陷入具体的技术细节。根据Gartner的研究报告，实施有效安全治理的企业，
    其安全事件发生率比未实施治理的企业低67%，同时安全运营成本降低40%，
    投资回报率（ROI）可达1:3.5。

    治理框架通常包括三个层次：战略层负责制定安全战略和资源分配；
    管理层负责将战略转化为具体的管理制度和流程；
    执行层负责日常的安全操作和技术实现。

    实施安全治理需要遵循：战略先行，从企业整体战略出发确定安全定位；
    体系保障，建立完整的组织、流程、技术体系；
    持续改进，根据内外部环境变化不断优化。
    ```

## A.7 [CODE:double] 代码示例

+   双栏代码（16-30 行）使用 `[CODE:double]` + `[LAYOUT:left-right]` 标注，左右栏各放一段逻辑相关的代码。

    ~~~markdown
    ### 权限控制实现

    ```python
    # 左栏：权限模型定义
    class Permission:
        """权限类：定义资源和操作"""
        def __init__(self, resource, action):
            self.resource = resource  # 资源标识
            self.action = action      # 操作类型

        def match(self, request):
            """匹配请求是否符合权限"""
            return (request.resource == self.resource and
                    request.action == self.action)

    class Role:
        """角色类：权限集合"""
        def __init__(self, name, permissions):
            self.name = name
            self.permissions = permissions

        def has_permission(self, perm):
            return perm in self.permissions

    # 右栏：权限验证器
    class SecurityManager:
        def __init__(self):
            self.roles = {}
            self.user_roles = {}

        def authorize(self, user, permission):
            roles = self._get_user_roles(user)
            return any(r.has_permission(permission) for r in roles)
    ```

    [LAYOUT:left-right]
    ~~~

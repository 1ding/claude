## 第零部分：Markdown输入解析规则

### 零、Markdown到HTML的映射关系

#### 0.1 标题层级映射

| Markdown标记 | 含义          | 对应HTML页面类型          | 使用的CSS类      |
| ------------ | ------------- | ------------------------- | ---------------- |
| `#`          | 文档标题页    | 标题页（Title Slide）     | `layout-title`   |
| `##`         | 章节分隔页    | 章节页（Section Divider） | `layout-section` |
| `###`        | 单页PPT       | 标题+内容页               | `layout-content` |
| `####`       | 单页PPT子主题 | 标题+内容页（面包屑三级） | `layout-content` |

**规则说明：**

```markdown
# 企业数字安全治理框架              → 标题页（layout-title）
**副标题文字**                       → title-subtitle
- 日期：2025-11-07                 → title-author

- 要点2

#### 子主题2                        → 新页面，面包屑: "父主题 › 子主题2"

```

#### 0.2 内容标注识别与处理

| Markdown标注      | 含义         | HTML处理方式                               |
| ----------------- | ------------ | ------------------------------------------ |
| `[KEY]`           | 核心信息强调 | 使用`.highlight`类包裹文字，或左侧加粗色条 |
| `[DATA]`          | 数据或数字   | 使用`.data-card`组件，大号数字+小标签      |
| `[CHART:bar]`     | 柱状图建议   | 使用CSS Grid创建简化柱状图视觉             |
| `[CHART:line]`    | 折线图建议   | 使用箭头符号或简化趋势展示                 |
| `[CHART:pie]`     | 饼图建议     | 使用百分比卡片网格展示                     |
| `[CHART:flow]`    | 流程图建议   | 使用带箭头的横向或纵向卡片链               |
| `[CHART:compare]` | 对比图建议   | 使用两栏布局或对比卡片                     |
| `[CHART:table]`   | 表格建议     | 使用网格布局或列表结构                     |
| `[CODE:single]`   | 单栏代码     | 使用`<pre><code>`，width: 740px            |
| `[CODE:double]`   | 双栏代码     | 使用两栏布局，每栏width: 355px             |

#### 0.3 布局选择策略

**自动布局选择流程：**

```
输入分析 → 标注统计 → 布局判定

1. 统计页面特征：
   - 要点数量
   - 标注类型
   - 代码块有无
   - 文字总量

2. 布局选择决策树：
   
   ├─ 如果有 [CODE:double]
   │   → 使用两栏布局 (layout-two-columns)
   │
   ├─ 如果有 [CHART:compare] 或成对的 [DATA]
   │   → 使用两栏布局 (layout-two-columns)
   │
   ├─ 如果有 4-6个 [DATA] 标注
   │   → 使用2×2或3×2网格布局
   │
   ├─ 如果要点数 ≥ 6 且字数少
   │   → 使用3列网格布局
   │
   └─ 其他情况
       → 使用标题+内容页 (layout-content)
```

### 三、布局框架规范

#### 3.1 标题页（Title Slide）

**对应Markdown：** `# 文档标题`

-   **特征**：无标题栏、无页脚、全屏渐变背景
-   **主标题**：top 165px, 字号26px, 水平居中
-   **副标题**：top 215px, 字号12px, 水平居中
-   **作者信息**：bottom 50px, 字号8px, 水平居中

#### 3.2 章节分隔页（Section Divider）

**对应Markdown：** `## 章节名称`

-   **特征**：简化的标题页样式，用于分隔主题
-   **章节标题**：top 180px, 字号22px, 水平居中
-   **渐变背景**：使用较浅的渐变色
-   **无页脚**

**HTML模板：**

```html
<div class="ppt-container layout-section">
  <div class="ppt-content" style="background: linear-gradient(135deg, #818cf8 0%, #a78bfa 100%);">
    <div style="position: absolute; top: 180px; left: 50%; transform: translateX(-50%); font-size: 22px; font-weight: 700; color: #ffffff; text-align: center; width: 700px;">
      章节标题
    </div>
  </div>
</div>
```

#### 3.3 标题+内容页（Title & Content）

**对应Markdown：** `### 页面标题` 或 `#### 子标题`

-   **标题栏**：top 30px, 高25px, 底部1px分隔线
-   **内容区**：top 66px, 宽740px × 高349px
-   **适用场景**：列表、段落、单一内容块

#### 3.4 两栏布局（Two Columns）

**触发条件：**

-   Markdown中包含 `[CODE:double]` 标注
-   包含 `[CHART:compare]` 标注
-   包含成对的 `[DATA]` 标注（2个或4个）

-   **左栏**：left 30px, width 355px, height 349px
-   **右栏**：left 415px, width 355px, height 349px
-   **栏间距**：30px
-   **内边距**：18px（可调整为14-16px）
-   **注意**：两栏直接放在ppt-content下，不要用content-box包裹

#### 3.5 网格布局（Multi-Content）

**触发条件：**

-   4-6个 `[DATA]` 标注 → 2×2或3×2网格
-   6-9个简短要点 → 3×3网格
-   3个主要模块 → 3列布局

-   **常用规格**：2×2、3×2、3列
-   **标准间距**：14px
-   **紧凑间距**：10-12px
-   **尺寸计算**：见第四章精确计算方法

### 四、精确计算方法（强制执行）

#### 4.1 基础计算公式

**多列布局（宽度）：**

```
每列宽度 = (740 - gap × (列数-1)) / 列数
```

**多行布局（高度）：**

```
每行高度 = (349 - gap × (行数-1)) / 行数
```

**元素坐标：**

```
left = 30 + i × (列宽 + gap)    // i从0开始
top = 66 + j × (行高 + gap)     // j从0开始
```

#### 4.2 常用布局精确尺寸

**2列布局（gap=30px）：**

```
列宽：355px
左列：left 30px, width 355px
右列：left 415px, width 355px
验证：30 + 355 + 30 + 355 = 770 ✓
```

**3列布局（gap=14px）：**

```
可用宽度：740 - 14×2 = 712px
分配：237px + 237px + 238px = 712px
位置：
  列1: left 30px
  列2: left 281px  (30+237+14)
  列3: left 532px  (30+237+14+237+14)
```

**2×2网格（gap=14px）：**

```
列宽：(740-14)/2 = 363px
行高：(349-14)/2 = 167.5px → 167px + 168px

位置矩阵：
  (行0,列0): left 30px,  top 66px,  363px × 167px
  (行0,列1): left 407px, top 66px,  363px × 167px
  (行1,列0): left 30px,  top 247px, 363px × 168px
  (行1,列1): left 407px, top 247px, 363px × 168px

验证：
  宽度: 363 + 14 + 363 = 740 ✓
  高度: 167 + 14 + 168 = 349 ✓
```

**3行垂直（gap=14px）：**

```
可用高度：349px
gap占用：14 × 2 = 28px
剩余高度：349 - 28 = 321px
每行分配：107px

位置：
  行1: top 66px,  height 107px
  行2: top 187px, height 107px  (66+107+14)
  行3: top 308px, height 107px  (187+107+14)

验证：107×3 + 14×2 = 349 ✓
```

### 五、生成规则（强制遵守）

#### 5.1 文件格式规则

1.   单文件HTML格式
2.   CSS内联在`<style>`标签中
3.   JavaScript内联在`<script>`标签中
4.   不依赖外部资源

#### 5.2 页面结构规则

1.   `#` 标题必须使用`layout-title`类
2.   `##` 标题必须使用`layout-section`类
3.   `###` 和 `####` 必须有标题栏和页脚
4.   面包屑标题：
     -   `###` 单独页面：显示为"父章节 › 页面标题"
     -   `####` 子页面：显示为"父标题 › 子标题"
5.   面包屑最多3级，使用›分隔符
6.   页脚左侧固定：`上海天帷智慧数字技术有限公司 / www.tenward.com`
7.   页脚右侧固定：`第 X 页`

#### 5.3 内容规范

1.   正文字号：13px（标准）、12px（紧凑）、11px（最小）
2.   行高：1.4-1.6（保证可读性）
3.   元素间距：≥10px（防止拥挤）
4.   卡片padding：12-18px（根据空间调整）

#### 5.4 标注处理规范

1.   **[KEY]标注**：使用`.highlight`类或左侧彩色条强调
2.   **[DATA]标注**：使用`.data-card`组件，大号数字+小标签
3.   **[CHART:*]标注**：根据类型创建简化视觉图形
4.   **[CODE:single]**：使用单栏代码块，width: 740px
5.   **[CODE:double]**：使用两栏布局，每栏width: 355px

#### 5.5 禁止项（零容忍）

```
❌ 严禁使用 overflow: hidden
❌ 严禁使用 overflow: auto
❌ 严禁使用 overflow-y: auto
❌ 严禁使用 overflow-x: auto
❌ 严禁使用任何形式的滚动条
❌ 严禁内容超出349px边界
❌ 严禁使用估算词汇（"约""大概""差不多"）
❌ 严禁省略计算步骤直接生成代码
❌ 严禁忽略Markdown中的标注信息
```

每个content-box必须添加计算注释：

3.   **选择页面布局**：根据第零章的映射规则选择合适的HTML布局
4.   **处理内容标注**：根据[KEY]、[DATA]、[CHART]等标注选择对应的CSS组件
5.   **精确计算布局**：使用第四章的计算方法确保内容不超出边界
6.   **生成HTML代码**：基于模板和计算结果生成完整HTML
7.   **验证质量**：检查页面类型映射、标注处理、尺寸计算是否正确

### 核心原则

**先解析，再映射，后计算，最终生成。**

-   ✅ 必须识别所有Markdown标注并正确处理
-   ✅ 必须根据内容特征选择最优布局
-   ✅ 必须精确计算，绝不估算
-   ✅ 必须保证所有内容在349px边界内

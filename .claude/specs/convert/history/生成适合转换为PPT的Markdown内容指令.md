# Markdown文档转PPT格式优化指令

> **版本**：v2.1
> **更新日期**：2025-11-07
> **使用场景**：已有Markdown文档，需要优化为适合PPT展示的格式
> **核心目标**：保持原有逻辑结构，优化内容密度，添加视觉化标注

---

## 一、使用说明

本指令用于将已有的Markdown文档优化为适合PPT展示的格式。

**执行原则：**

1.   **保持逻辑结构**：不改变原文档的章节顺序和核心观点
2.   **保持内容完整性**：不得忽略、跳过或删减原文档的内容和要点，如单页内容过多应分页展示
3.   **控制页面容量**：每页内容适合通过一个PPT页展示
4.   **优化表达方式**：将段落文字转换为结构化要点，精简冗余表述
5.   **提供可视化建议**：以标注的形式提供PPT可视化建议

## 二、标题层级规则

### 2.1 层级定义

| 层级         | 语法   | 用途       | 数量 | 说明                               |
| ------------ | ------ | ---------- | ---- | ---------------------------------- |
| **文档标题** | `#`    | 封面页     | 1个  | 包含标题、副标题、日期             |
| **章节标题** | `##`   | 章节分隔页 | 不限 | 大章节的起始页，仅标题             |
| **主页面**   | `###`  | 标准内容页 | 不限 | 每个###独立成页                    |
| **子页面**   | `####` | 主题细分   | 可选 | 从属于###，标题显示为"主题/子主题" |

### 2.2 层级使用规范

**正确示例：**

```markdown
    # 数字安全治理框架

    ## 第一章：治理概述

    ### 治理体系架构
    - 内容...

    #### 组织架构
    - 内容...（显示为"治理体系架构/组织架构"）

    #### 职责矩阵
    - 内容...（显示为"治理体系架构/职责矩阵"）

    ### 治理流程设计
    - 内容...

    ## 第二章：实施路径
    ...
```

**错误示例：**

```markdown
    ### 主题
    #### 子主题
    ##### 五级标题  ❌ 不允许超过4级
```

## 三、内容限制规则

### 3.1 页面容量标准

| 元素           | 限制      | 说明                         |
| -------------- | --------- | ---------------------------- |
| **页面标题**   | ≤20字     | 清晰、有力、可独立理解       |
| **要点数量**   | 5-8条     | 最少3条，最多10条            |
| **单条要点**   | 20-50字   | 完整表达，保持精炼           |
| **页面总字数** | 400-500字 | 不含代码和标注，充分展开说明 |
| **代码行数**   | ≤50行     | 单块代码的限制               |
| **列表嵌套**   | ≤3层      | 主要点→次要点→细节点         |

### 3.2 字数计算规则

```
页面字数 = 标题字数 + 所有要点字数 + 补充说明字数
不计入：代码块、标注标签、分隔符
```

### 3.3 内容密度参考

-   **高密度页**（450-500字）：概念深入解释、复杂流程说明、多维度分析
-   **标准密度页**（400-450字）：框架介绍、方法论说明、实施步骤
-   **中密度页**（350-400字）：要点列举、对比分析、案例说明
-   **低密度页**（300-350字）：数据展示为主、简单流程、关键结论
-   **极简页**（<300字）：章节封面、引用金句、单一图表

    ### 权限控制完整实现

    ```python
    # 左栏：权限模型定义
    class Permission:
        """权限类：定义资源和操作"""
        def __init__(self, resource, action, conditions=None):
            self.resource = resource      # 资源标识
            self.action = action          # 操作类型
            self.conditions = conditions  # 附加条件

        def match(self, request):
            """匹配请求是否符合权限定义"""
            return (request.resource == self.resource and
                    request.action == self.action and
                    self._check_conditions(request))

        def _check_conditions(self, request):
            """检查附加条件"""
            if not self.conditions:
                return True
            return all(cond(request) for cond in self.conditions)


    class Role:
        """角色类：权限集合"""
        def __init__(self, name, permissions):
            self.name = name
            self.permissions = permissions

        def has_permission(self, permission):
            """检查角色是否包含指定权限"""
            return permission in self.permissions

    # 右栏：权限验证器
    class SecurityManager:
        """安全管理器：统一权限验证"""
        def __init__(self):
            self.roles = {}           # 角色注册表
            self.user_roles = {}      # 用户角色映射

        def authorize(self, user, permission):
            """权限验证主入口"""
            # 1. 验证用户身份
            if not self._authenticate(user):
                return False

            # 2. 获取用户角色
            roles = self._get_user_roles(user)

            # 3. 检查角色权限
            for role in roles:
                if role.has_permission(permission):
                    self._audit_log(user, permission, True)
                    return True

            self._audit_log(user, permission, False)
            return False

        def _get_user_roles(self, user):
            """获取用户的所有角色"""
            return [self.roles[r] for r in self.user_roles.get(user.id, [])]
    ```

## 七、禁止事项

### 7.1 格式禁止

| 禁止                     | 替代方案                      |
| ------------------------ | ----------------------------- |
| 单页超过500字            | 分页展示或精简内容            |
| 段落文字（>3行连续文本） | 提炼为5-8个要点               |
| 复杂长句（>50字）        | 拆分为多个短句                |
| 代码超过50行             | 分页展示或简化示例            |
| Markdown表格             | 用要点列举或标注[CHART:table] |
| 5层以上标题              | 最多4层（# ## ### ####）      |
| 超过10个要点             | 分页或分组展示                |
| 4层以上嵌套列表          | 简化为3层或拆分页面           |

### 7.2 内容禁止

**严格禁止的内容处理行为：**

-   ❌ **忽略原文档内容**：不得跳过原文档中的任何章节、段落或要点
-   ❌ **删减原文档要点**：不得因为字数限制而删除原文档的关键信息
-   ❌ **随意合并内容**：不得将多个不同主题的内容强行合并到一页
-   ❌ 大量专业术语不加解释
-   ❌ 纯文字页面无视觉元素
-   ❌ 重复内容（标题与要点重复）
-   ❌ 模糊表述（"可能"、"大概"、"一些"）
-   ❌ 缺少逻辑连接（页面之间跳跃）

**正确做法：**

-   ✅ 保留原文档的所有内容和要点
-   ✅ 如果单页内容过多，应该分成多页展示
-   ✅ 如果原文档有重复内容，可以适当精简表述但不能删除核心信息
-   ✅ 优化表达方式而非删减内容

### 7.3 标注禁止

-   ❌ 滥用标注（每条都标[KEY]）
-   ❌ 标注不准确（普通内容标[DATA]）
-   ❌ 缺少必要标注（关键数据不标注）

## 八、特殊场景处理

当遇到以下特殊情况时，需要特别处理：

### 场景1：原文档包含大量表格

**处理方式：**

-   简单表格（2-3列）：转换为要点列举
-   复杂表格（4列以上）：标注`[CHART:table]`建议可视化
-   对比表格：标注`[CHART:compare]`
-   数据表格：根据数据类型选择合适的图表标注

### 场景2：原文档代码示例较多

**处理方式：**

-   每个代码块严格控制在50行以内
-   保留最核心的逻辑代码，移除辅助性代码
-   为每个代码块添加清晰的注释说明
-   根据行数标注`[CODE:single]`（≤25行）或`[CODE:double]`（26-50行）
-   配置文件标注`[CONFIG]`，命令行标注`[CMD]`

### 场景3：原文档概念密集

**处理方式：**

-   识别核心概念并标注`[KEY]`
-   每页不超过3-4个核心概念
-   为复杂概念补充类比或例子
-   添加`[CHART:flow]`等视觉化标注辅助理解
-   必要时将一个概念拆分为多页讲解

### 场景4：原文档数据丰富

**处理方式：**

-   所有关键数据必须标注`[DATA]`
-   核心指标标注`[EMPHASIS:number]`用于大号展示
-   根据数据特点建议图表类型：
    -   对比数据 → `[CHART:bar]`
    -   趋势数据 → `[CHART:line]`
    -   占比数据 → `[CHART:pie]`
    -   多维数据 → `[CHART:table]`
-   确保数据展示的逻辑性和可读性

### 9.2 全文检查

**结构层面：**

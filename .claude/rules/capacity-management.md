# 容量管理规范

本规范为常驻规则，适用于所有会话中的每一轮交互。无需在各指令中重复定义容量检查逻辑。

## 容量公式

```
已用 = Σ [LOADED *] tokens          ← 文件加载（输入侧）
     + Σ [CAP DELTA] chars ÷ 3.5   ← 文件写出（输出侧）
     + 50K                           ← 对话固定储备

剩余 = 200K - 已用
```

- 换算比：bytes ÷ 3.5 ≈ tokens（中文技术文档，误差约 ±20%）

## [CAP DELTA] 标记规范

每次向文件写入内容后（Write / Edit 工具执行后），立即输出：

```
[CAP DELTA] +{N} chars (~{M} tokens) → {文件路径}  |  本会话输出侧累计: ~{T} tokens
```

- N：本次写入字符数；M = N ÷ 3.5 取整；T：历史所有 [CAP DELTA] M 值之和

## 全局触发点

### 触发点1：收到用户输入后、执行前

由 UserPromptSubmit hook 强制注入指令执行，不依赖本规则文件。

### 触发点2：Skill 执行前

由 PreToolUse hook（匹配 Skill 工具）强制注入，在每个 skill 启动前执行。

### 触发点3：准备生成重量级输出前（> 1K tokens）

1. 重新计算当前剩余量
2. 剩余 > 20K → 继续输出
3. 剩余 < 20K → 触发决策树

## 决策树

触发条件：剩余 < 20K，或预估后当前会话无法完成任务。

```
当前会话能完成任务？
├── YES → 继续执行
└── NO  → 内容强耦合，拆解会损害质量？
          ├── YES → 提示：切换到 1M 上下文模型（claude-sonnet-4-6[1m] 或 claude-opus-4-6）
          └── NO  → 任务剩余部分（新会话重新开始）能在 180K 内完成？
                    ├── YES → 写交接文件 → 停止执行 → 告知用户如何继续
                    └── NO  → 提示：任务需分解，超出单次会话处理能力
```

**"合适新会话"的判断**：任务剩余部分所需输入文件 + 预估输出 ≤ 180K

**"内容强耦合"的判断标准**：满足以下任一条件时认定为强耦合：
- 核心文档单体超过 80K tokens，且各章节存在大量交叉引用
- 任务要求同时对照 ≥ 5 个关联文档进行一致性推断
- 拆解后单个子任务无法自包含（必须引用其他子任务的中间结论）

## 交接计划（"合适新会话"时生成）

- 路径：`projects/{项目}/plans/交接_{文档名}_{YYYYMMDDHHmm}.md`
- 格式见 `.claude/rules-ext/handoff-template.md`
- 内容：已完成部分、断点位置、下次会话所需加载文档列表、继续命令
- 生成后告知用户：**新对话中输入 `/session-resume projects/{项目}/plans/交接_{文档名}_{时间戳}.md` 继续工作**

## 豁免操作

以下操作输出侧开销极小，hook注入的触发点1和触发点2可跳过**输出侧**估算（触发点3仍生效）：

- `/doc-outline`（生成大纲）
- `/doc-init`（初始化项目目录）
- `/doc-promote`（版本晋升，不加载文档内容）
- `/session-minutes`（会话纪要，设计为容量紧张时可用）
- `/cap-status`（容量查询本身）
- `/session-resume`（交接恢复，仅加载交接文件本身）

> 注：`/doc-fix` 已从豁免列表移除。虽然输出侧开销小，但输入文件可能较大，须执行输入侧预检（见 doc-fix.md）。

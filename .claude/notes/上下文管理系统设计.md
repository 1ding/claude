# 工作区系统设计文档

+   涵盖：目录结构与职责、各 skill/规则/脚本说明、上下文管理系统设计。

## 一、目录结构

### 顶层布局

```text
claude/
├── .claude/
│   ├── commands/          # Skill 命令定义
│   ├── notes/             # 系统设计说明文档（本文件所在位置）
│   ├── rules/             # 核心行为规则（Claude Code 自动加载）
│   ├── rules-ext/         # 补充规则、模板、清单（doc-* 按需加载）
│   ├── scripts/           # 工具脚本（python/bash）
│   └── specs/             # 规范文件（自有展开）
├── projects/
│   └── {项目名}/
└── claude.md
```

### .claude/ 各子目录职责

| 子目录          | AI 读写权限           | 说明                                               |
| --------------- | --------------------- | -------------------------------------------------- |
| `commands/`     | 只读                  | Skill 命令定义，通过 /skill-name 触发              |
| `notes/`        | 只读                  | 系统设计说明文档（非运行时文件）                   |
| `rules/`        | 只读                  | 核心行为规则，Claude Code 自动加载                 |
| `rules-ext/`    | 只读                  | 补充规则、模板、清单，doc-* 命令按需读取           |
| `scripts/`      | 只读（bash 调用执行） | 版本管理工具脚本                                   |
| `specs/common/` | 只读                  | C 系列通用规范 schema                              |
| `specs/domain/` | **读写**（AI 工作区） | 领域规范工作区，AI 在此编写/修订规范，遵循版本管理 |

+   `specs/domain/` 是规范文档的专属工作区，AI 可读写；其他 `.claude/` 子目录由用户手动维护，AI 不直接写入。

## 二、commands/ —— Skill 命令

### 通用参数约定

+   **路径内联**：所有 doc-* 命令支持直接传入文件路径，无需先执行 `/load-target`：

```text
/doc-fix /path/to/doc.md [N 或 N-M] 修正指令
/doc-write /path/to/doc.md 编写指令
```

+   路径置于第一位，可附章节参数（`N` 仅加载第 N 章，`N-M` 加载第 N 至 M 章）；路径之后的内容视为指令输入。

### 加载命令（/load-*）

+   每条加载命令执行后均执行以下固定步骤：

-   输出加载确认：`[LOADED {type}] {路径} | ~{tokens} tokens`（有章节参数时附 `[章节 N]` 或 `[章节 N-M]`）
-   汇总本次会话全部 `[LOADED *]` 记录，列出文件清单及估算合计 tokens

+   **章节参数**（仅支持 .md 文件）：路径后附 `N`（单章节）或 `N-M`（连续多章节）。按一级标题 `#` 切分，序号从 1 起；无标题或序号越界时加载全文并告警。两类命令均执行容量检查；单文件时均支持章节参数（.md 文件限定）。

+   **A 类 — 仅支持单文件**

| 命令          | 参数格式                   | LOADED  | 场景                     |
| ------------- | -------------------------- | ------- | ------------------------ |
| /load-target  | `路径`（必填）`[N 或 N-M]` | target  | doc-* 操作前加载目标文档 |
| /load-outline | `路径`（必填）`[N 或 N-M]` | outline | doc-write 时按大纲编写   |

+   **B 类 — 支持单文件 / 多文件 / 目录**

统一格式：`路径 [N 或 N-M]` 或 `路径1 路径2 ...` 或 `目录/`；load-layout / load-style 可无参（自动查找默认规范）。

| 命令             | LOADED                                                | 场景                           |
| ---------------- | ----------------------------------------------------- | ------------------------------ |
| /load-upstream   | upstream                                              | 修订/对齐前加载上游约束        |
| /load-downstream | downstream                                            | 上游改动后加载下游做一致性检查 |
| /load-parallel   | parallel                                              | 同阶段其他模块一致性对齐       |
| /load-context    | context                                               | 编写前加载过程/背景约束        |
| /load-refs       | refs                                                  | 编写/修订时提供参考素材        |
| /load-layout     | layout                                                | 格式修订或编写前加载排版规范   |
| /load-style      | style                                                 | 规范驱动修订前加载语言风格规范 |
| /load-domain     | domain                                                | 编写前加载 S/P/N 系列文档骨架  |
| /load-spec       | spec                                                  | 规范类型不明确时使用           |
| /load-relations  | AI 判断（upstream / downstream / parallel / context） | 关联类型不明确或批量加载时     |

+   **补充说明：**

-   **文件类型**：target / layout / style / domain / spec 支持 .md 和 .yaml；其余命令仅支持 .md
-   **目录模式**：所有命令均扫描支持的文件类型，同名前缀取最新版本
-   **upstream / downstream / parallel**：按指令词直接标记关联类型，无需读取 CLAUDE.md
-   **relations**：有项目 CLAUDE.md 时从中批量解析关联类型；无 CLAUDE.md 时 AI 根据文件内容判断

### `/load-status`

+   **用法**：`/load-status`（无参数）
+   **功能**：扫描当前会话历史，汇总所有 `[LOADED *]` 记录
+   **输出**：加载文档清单（类型/路径/token 估算），显示合计 token 数及占 200K 基准的比例
+   **注意**：仅统计已加载文件 tokens，不含系统 prompt/对话记录等固定开销；综合容量评估用 `/cap-status`
+   **场景**：执行 doc-* 前核查上下文是否完整；排查是否遗漏加载某类文档

### `/cap-status`

| 属性 | 内容                                                                                  |
| ---- | ------------------------------------------------------------------------------------- |
| 用法 | `/cap-status`（无参数）                                                               |
| 功能 | 估算会话总体容量：Σ[LOADED *] + Σ[CAP DELTA]÷3.5 + 30K 固定储备                       |
| 输出 | 分项明细（输入侧/输出侧/固定储备）+ 总计 + 剩余 + 状态（充裕 >50K / 偏紧 20K–50K / 不足 <20K） |
| 场景 | 随时查询当前容量；容量紧张时决策是否切换模型（`/model sonnet-1m`）                    |

### `/doc-fix`

+   **用法**：`/doc-fix [路径 [章节]] 修正指令`；路径可选，有路径则内联加载，无路径从会话历史取 [target]
+   **功能**：小范围局部修正（错别字/单术语替换/少量补充或删减）；不加载规范或关联文档，不做质量检查
+   **输出**：`drafts/{文档}_v{ver}_R{n}@{时间戳}.md`；简报（修改内容/涉及位置/新文件名）含提示"未执行规范和一致性检查"
+   **场景**：发现少量明确问题需立即修正；处理验证报告中的已知简单问题
+   **不适用**：超过 3 处不相关的修改/需要规范对标/需要跨文档一致性 → 改用 `/doc-revise`

### `/doc-write`

+   **用法**：`/doc-write [路径 [章节]] [编写指令]`；路径可选内联；推荐预先加载 [domain] / [upstream] / [refs]
+   **前置条件**：[target] 或 [outline]（可路径内联满足）
+   **流程**：三阶段：阶段零（输入评估与规划）→ 阶段一（执行编写）→ 阶段二（质量复核与汇总）
+   **自动加载**：structure-constraints（始终）；quality-checklist（阶段二）；handoff-template（容量不足时）；decisions-template（需裁决时）
+   **编写后**：自动执行 R→常规版本号，调用 validate-all.sh 验证，输出 [CAP DELTA] 标记
+   **输出**：`drafts/{文档}_v0.01_R01@...md` → 完成后转 `drafts/{文档}_v0.01@...md`；容量不足时生成 `plans/交接_XXX.md`
+   **交互**：阶段零确认编写范围和规划；遇矛盾请用户裁决
+   **场景**：全新文档首次编写（从大纲或目标文档开始）

### `/doc-revise`

+   **用法**：`/doc-revise [路径 [章节]] [修订指令]`；一致性驱动时建议预先加载 [upstream] / [downstream] / [parallel]
+   **前置条件**：[target]（可路径内联满足）
+   **驱动类型**：9 种：意见驱动 / 规范驱动 / 参考吸纳驱动 / 一致性驱动 / 质量自检驱动 / 改写重构 / 增补扩写 / 精简删减 / 版本升级
+   **流程**：三阶段（同 doc-write）
+   **自动加载**：structure-constraints（始终）；quality-checklist（阶段二）；association-rules（一致性驱动时）；handoff-template（容量不足时）；decisions-template（需裁决时）
+   **修订后**：保持 R 版本命名（不自动转常规版本），调用 validate-all.sh 验证，输出 [CAP DELTA] 标记
+   **输出**：`drafts/{文档}_v{ver}_R{n}@{时间戳}.md`；容量不足时生成 `plans/交接_XXX.md`
+   **交互**：同 doc-write
+   **场景**：按用户修订意见系统性更新文档；规范发布后对已有文档做规范对标；上游变更后同步下游
+   **不适用**：1-2 处小问题 → `/doc-fix`；只调格式 → `/doc-fmt`；只做跨文档比对不修 → `/doc-align`

### `/doc-review`

+   **用法**：`/doc-review [路径 [章节]] [评审重点]`；可选预先加载 [spec] / [layout] / [style]
+   **前置条件**：[target]（可路径内联满足）
+   **检查维度**：10 个：术语一致性 / 交叉引用 / 数据流 / 逻辑一致性 / 格式一致性 / 规范符合性 / 表述清晰度 / 内容完整性 / 结构约束 / 脚本自动验证（validate-all.sh）
+   **输出**：评审报告（问题分级：`[!!]` 严重 / `[!]` 一般 / `[OK]` 通过；含建议后续操作）；只报告，不修改文档
+   **场景**：编写/修订完成后提交前验收；定期质量审查；跨文档一致性检查用 `/doc-align`

### `/doc-fmt`

+   **用法**：`/doc-fmt [路径 [章节]] [格式重点]`；建议预先加载 [layout]（未加载则按通用 Markdown 规范执行）
+   **前置条件**：[target]（可路径内联满足）
+   **检查维度**：6 个：标题层级 / 表格格式 / 列表格式 / 代码块 / 表述风格 / 结构要求
+   **输出**：格式检查报告（问题列表，含位置/维度/严重程度）；确认修正后创建 `drafts/{文档}_v{ver}_R{n}@{时间戳}.md`，输出 [CAP DELTA]
+   **交互**：报告后询问"修正 / 修正+序号 / 不修正"
+   **场景**：内容完成后做格式规范整理；规范发布后对已有文档做格式合规检查

### `/doc-align`

+   **用法**：`/doc-align [路径 [章节]] [关联类型] [比对范围]`
+   **模式**：**标准模式**：[target] + 至少一个关联文档（upstream/downstream/parallel/context）；**对等模式**：无 [target]，两个以上 [parallel]
+   **功能**：按 association-rules.md 各关联类型比对维度执行系统性比对
+   **输出**：差异报告（差异点/涉及位置/严重程度）；修正时创建 `drafts/{文档}_v{ver}_R{n}@{时间戳}.md`，输出 [CAP DELTA]
+   **交互**：差异报告后询问修正哪些差异；对等模式须用户决策修哪份文档
+   **场景**：上游文档更新后检查下游是否同步；并行文档（同阶段多模块）术语/接口对齐

### `/doc-outline`

| 属性 | 内容                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------- |
| 用法 | `/doc-outline [路径 [章节]] [大纲生成指令]`；无强制前置加载；可选 [spec] / [domain] / [upstream]                  |
| 功能 | 新文档大纲生成（从零）或更新已有文档大纲；结合已加载规范和上游约束确定骨架；读取 decisions.md（若能推断项目路径） |
| 输出 | `plans/大纲_{目标文档名}.md`                                                                                      |
| 场景 | 编写新文档前先生成大纲与用户确认结构；文档内容扩展前重新规划骨架                                                  |

### `/doc-promote`

+   **用法**：`/doc-promote [路径或前缀] [版本号]`；有路径（含 `/` 或 `.md`）直接定位；有前缀取 drafts/ 最新；无参数取 [target]
+   **版本号**：可选，格式 `v\d+\.\d+`；不提供则默认 +0.01
+   **功能**：R 版本：调用 r-to-regular.py 执行 R→常规版本号；常规版本：跳过转换直接晋升；清理 drafts/ 历史版本（只保留最新文件）
+   **输出**：`outputs/{文档}_v{新版本}@{时间戳}.md`（正式版本）；旧正式版移至 `history/`；操作结果报告（版本变更/清理数量）
+   **场景**：修订完成用户确认后发布正式版本；一键替代"R转常规版本号 + 复制到 outputs/"

### `/doc-resume`

+   **用法**：`/doc-resume [交接文件名或路径]`；支持：`按 交接_XXX 继续` / 直接传路径；也可由自然语言触发（识别 `交接_` 关键词）
+   **功能**：读取 plans/ 交接文件（断点/需加载文档列表/决策记录/开放问题）；自动加载所需文档；跳过阶段零从断点续写/续改
+   **自动加载**：structure-constraints（始终）；其余按交接文件 `## 需加载文档` 列表
+   **输出**：恢复确认报告（断点/已加载文档/即将继续内容）；后续输出同 doc-write/doc-revise；全部完成后清理交接文件
+   **场景**：上次编写/修订因容量不足中断，在新会话继续

### `/doc-status`

| 属性 | 内容                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------- |
| 用法 | `/doc-status [项目名]`；无参数列出 `projects/` 下所有项目供选择                                    |
| 功能 | 读取项目 CLAUDE.md（领域/文档关联表）；扫描 refs/ / drafts/ / plans/ / outputs/ 汇总文件状态和进度 |
| 输出 | 项目状态报告（文档清单/状态/位置/进度/备注；参考材料数/计划文件数/待处理事项/建议下一步操作）      |
| 场景 | 会话开始时快速了解项目状态；多文档并行时确认哪些文档需要推进                                       |

### `/doc-init`

| 属性 | 内容                                                                                                                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用法 | `/doc-init 项目名 [领域] [文档清单]`；项目名必填；领域未指定则询问；文档清单可选（未提供则生成带占位说明的模板）                                                                              |
| 功能 | 创建标准目录结构（refs/ drafts/ plans/ outputs/ history/）；生成 CLAUDE.md（领域声明+文档关联表）；读取 decisions-template.md 生成空的 decisions.md；验证领域 specs/{领域}/CLAUDE.md 是否存在 |
| 输出 | `projects/{项目名}/` 下的完整目录结构和配置文件                                                                                                                                               |
| 场景 | 启动新项目时初始化工作目录；建立规范的项目文档结构                                                                                                                                            |

### `/spec-to-schema`

+   **用法**：`/spec-to-schema <规范文档路径>`；也可从会话历史 [target] 或 [spec] 记录获取
+   **功能**：读取规范文档，提取强制规则/判断标准/格式要求/关键示例；删除背景介绍/详细解释/教学性内容
+   **输出**：`{规范文档所在目录}/../schema/{规范文档完整文件名（含.md）}.schema.yaml`；生成报告（规则数/保留示例数）
+   **Schema 命名约定**：schema 文件名 = 规范文档完整文件名（含版本号、时间戳、`.md` 后缀）+ `.schema.yaml`，例：`C01-内容表达规范_v0.02@202603041608.md.schema.yaml`
+   **场景**：规范定稿后生成 schema，供 /load-domain 等以低 token 消耗加载；规范更新后同步更新 schema

### `/schema-validate`

| 属性 | 内容                                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用法 | `/schema-validate <规范文档路径>`；自动从规范文档路径推导 schema 路径（`../schema/{规范文档完整文件名}.schema.yaml`）；找不到精确版本时搜索同前缀旧版本 |
| 功能 | 读取规范文档与 schema，逐项比对；检测：遗漏规则、描述偏差、schema 未同步、文件名版本不匹配；发现 [!!] 问题时直接修正 schema 并重命名文件                |
| 输出 | 验证报告（[OK]/[!]/[!!] 分级）+ 修正 schema 文件 + [CAP DELTA] 标记（若有写入）                                                                         |
| 场景 | 规范更新后验证 schema 是否需要同步；/spec-to-schema 执行后的验收检查；定期批量验证所有 schema                                                           |

### `/session-minutes`

+   **用法**：`/session-minutes [输出路径] [重点范围]`；输出路径默认 `sessions/纪要_{YYYYMMDD_HHmm}.md`；重点范围可选（如"只记录决策"；不指定则全面记录）
+   **功能**：扫描会话历史，提取：已加载文档列表/当前任务状态与进度/决策记录/开放问题/下一步；生成结构化纪要，含"新会话启动指引"（按序列出需重新执行的 /load-* 命令）
+   **容量**：本命令自身开销极低，容量紧张时仍可执行
+   **输出**：`sessions/纪要_{时间戳}.md`（含：上下文文档/进度断点/决策/开放问题/新会话启动操作序列）
+   **场景**：`/cap-status` 显示 ⚠️ 或 🔴，需要迁移到新会话；阶段性工作完成后留存决策记录
+   **说明**：若有 `plans/` 计划文件，新会话优先用 `/doc-resume` 恢复，纪要作为补充上下文

## 三、rules/ —— 核心规则（自动加载）

### `version-management.md`

+   **加载时机**：Claude Code 自动加载，每次会话全程有效，无需手动操作
+   **文件命名**：临时版本：`{文件名}_v{版本}_R{修订}@{时间戳}.md`；常规版本：`{文件名}_v{版本}@{时间戳}.md`
+   **目录职责**：drafts（工作区，保留全部历史）/ outputs（当前正式版，不含 R）/ history（旧正式版归档）
+   **版本流转**：日常修订：R 编号递增，版本号不变；R 转常规版本号（明确指令触发）：版本号 +0.01，R.xx 归并为一条；提交 outputs（明确指令触发）：先转常规版本，再复制到 outputs/
+   **场景**：所有文档创建/修订操作的命名与版本流转依据；/doc-promote 执行的规范基础

### `capacity-management.md`

## 七、上下文管理系统

### 设计背景

+   旧系统每次调用 doc-* skill 时自动加载所有规范，单次基础开销约 ~39,700 tokens（规范 schema × 4 + 领域规范 × 3 + 容量管理 + 目标文档类型规范）。大文档场景（目标 ~32K + 上游 ~115K）开局即逼近 200K 软基准，且用户对加载内容和容量消耗完全无可见性。

### 设计目标

| 目标         | 说明                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| 用户显式控制 | 所有文件加载由用户通过 /load-* 命令触发，无隐式默认加载                            |
| 容量实时可见 | 每次加载后显示 token 估算；每次写出后输出 [CAP DELTA]；随时 /cap-status 查综合余量 |
| 集中管理     | 容量检查逻辑集中在 rules/capacity-management.md，各指令不嵌入容量评估逻辑          |
| 操作语义不变 | doc-* 功能和输出格式保持不变，仅去掉自动加载和内嵌容量评估步骤                     |

### 核心机制一：[LOADED] 状态标记（输入侧）

```text
[LOADED {type}] {路径} | ~{tokens} tokens
```

+   type 可取值：`target`、`outline`、`upstream`、`downstream`、`parallel`、`context`、`refs`、`layout`、`style`、`domain`、`spec`

+   doc-*命令通过扫描会话历史中的 [LOADED*] 标记来：

-   验证先决条件是否满足（缺少则中止并提示）
-   获知哪些文件已在上下文中，无需重复读取
-   推断可用的规范和关联文档

### 核心机制二：[CAP DELTA] 写出标记（输出侧）

```text
[CAP DELTA] +{N} chars (~{M} tokens) → {文件路径}  |  本会话输出侧累计: ~{T} tokens
```

+   每次向 drafts/ 写入文件后立即输出，记录本次写入字符数和累计输出侧 tokens
+   N：本次写入字符数；M = N ÷ 3.5 取整；T：本会话历史所有 M 值之和

### 容量公式

```
已用 = Σ [LOADED *] tokens + Σ [CAP DELTA] chars ÷ 3.5 + 30K（固定储备）
剩余 = 200K - 已用
```

| 剩余区间           | 状态   | 行为                                      |
| ------------------ | ------ | ----------------------------------------- |
| > 50K（>25%）      | 充裕 | 正常执行                                  |
| 20K–50K（10%–25%） | 偏紧 | 注意后续任务规模                          |
| < 20K（<10%）      | 不足 | 触发四分支决策树（继续/交接/切换1M/分解） |

### Token 估算

-   **公式**：文件字节数 ÷ 3.5（中英混合内容经验值，精度 ±20%）
-   **固定储备**：30K tokens/会话（系统 prompt + 版本管理规则 + 容量规则 + 对话积累）

### 典型工作流

+   **场景 A：局部快修（最小加载）**

```text
/doc-fix projects/ClariSphere/drafts/02-宏观需求_v0.11.md 将第3章的"用例"统一改为"使用场景"
```

+   预计：~8K（固定）+ ~32K（目标文档）= ~40K tokens

+   **场景 B：规范驱动修订**

```text
/load-target  projects/ClariSphere/drafts/02-宏观需求_v0.11.md
/load-style   .claude/specs/common/schema/C01-内容表达规范_v0.22@...yaml
/load-layout  .claude/specs/common/schema/C02-排版格式规范_v0.21@...yaml
/cap-status                                  ← 确认容量充裕
/doc-revise 规范驱动修订，对标 C01/C02 要求
```

+   **场景 C：大文档一致性对齐**

```text
/cap-status                                                         ← 会话初始确认
/load-target   projects/ClariSphere/drafts/02-宏观需求_v0.11.md     ← ~32K
/load-upstream projects/ClariSphere/outputs/01-战略规划_v0.11.md    ← ~115K

```

### 已知约束

| 约束                   | 说明                                          |
| ---------------------- | --------------------------------------------- |
| 状态仅会话内有效       | [LOADED] 标记不跨会话，新会话须重新 /load-*   |
| 已读入内容无法删除     | Claude 上下文窗口只追加，/unload 不可行       |

| 目录模式依赖 CLAUDE.md | /load-upstream 等目录模式需项目已配置关联关系 |

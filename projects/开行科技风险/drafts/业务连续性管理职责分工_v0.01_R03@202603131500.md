# 1 总则

+   **文档编号**：开行科技风险-REF-002
+   **文档名称**：业务连续性管理职责分工
+   **文档密级**：内部资料
+   **编写目的**：厘清业务连续性管理（BCM）在银行级与信息科技部内部的职责边界，明确安全管理团队与运维团队各自承担的管理活动，为信息科技部 BCM 体系建设与运营提供职责依据。
+   **适用范围**：适用于信息科技部安全管理团队、运维团队及相关管理人员。

# 2 三层职责架构

+   BCM 的职责分布于三个层级，各层级定位不同，形成管理与执行分离的结构：

    -   **银行级**：风险管理部牵头，负责全行 BCM 制度框架的建立、总体要求的提出以及跨部门统筹
    -   **科技管理级**：信息科技部安全管理团队，作为科技侧 BCM 的评估者、要求提出者和鉴证者，支撑 CIO 对 BCM 工作的决策与管控
    -   **科技执行级**：信息科技部运维团队，负责科技侧 BCM 的全部技术执行工作

+   安全管理团队同时承担两项结构性职能：对外是信息科技部与风险管理部之间的统一接口，对内是科技部内部的 BCM 管理协调层。这一定位决定了安全管理团队必须拥有实质性的管理权（评估权、标准制定权、鉴证权），而非仅作为传递层。

# 3 安全管理团队的职责

## 3.1 对外接口

+   承接风险管理部的 BCM 制度要求，转化为科技侧可落地的实施方案。
+   代表信息科技部参与全行 BCM 工作组及相关评审会议。
+   向风险管理部报送科技侧 BCM 执行情况。

## 3.2 评估整体 BCM 能力

+   安全管理团队从业务视角评估科技侧整体 BCM 能力：信息科技作为一个整体，能否支撑业务连续性要求。评估对象是 BCM 体系本身，而非单个系统的技术细节。
+   评估的参照系来自两个方向：一是风险管理部 BIA 输出的业务连续性要求（关键业务及其 RTO/RPO）；二是监管对 BCM 的规范性要求（演练频次、预案覆盖率、恢复能力验证等）。
+   评估维度包括：

    -   **覆盖完整性**：关键系统是否全部纳入 BCM 管理范围，是否存在管理空白
    -   **目标达成度**：整体 RTO/RPO 达标率处于什么水平，是否满足业务和监管要求
    -   **体系成熟度**：预案编制质量、演练频次、整改闭环机制是否完善

+   具体系统的技术现状数据（灾备架构、恢复时间实测值、备份成功率等）由运维团队提供；安全管理团队基于这些数据作出整体能力判断，不介入单个系统的技术分析。

## 3.3 提出目标要求

+   基于差距评估，向运维团队提出 BCM 能力提升的目标要求，包括目标值和达标时限。
+   审核运维团队提交的技术实施方案是否满足目标要求，不介入技术方案设计。
+   涉及跨团队协调时（如需开发团队配合应用级容灾设计、数据团队调整备份恢复策略），负责协调推动。

## 3.4 制度与标准

+   制定科技侧 BCM 管理制度、应急预案编制规范、演练管理办法。
+   定义科技侧 BCM 考核指标体系：

    -   演练覆盖率：关键系统年度演练覆盖情况
    -   恢复成功率：演练中实际达到 RTO/RPO 要求的比例
    -   预案更新及时率：系统变更后预案同步更新的完成率

+   随监管要求变化和业务架构调整，持续更新标准。

## 3.5 鉴证与验证

+   **演练事前**：向运维团队提出演练覆盖率要求（如"关键系统每年至少完整演练一次"）。
+   **演练事中**：现场独立鉴证，记录实际恢复时间、操作规范性及 RTO/RPO 达标情况。
+   **演练事后**：出具独立评估意见，对未达标项明确整改要求，跟踪复验结果。
+   **日常检查**：定期检查备份执行情况，包括备份成功率和恢复测试记录。
+   鉴证须由安全管理团队独立完成，不接受运维团队自评结果替代鉴证意见。

## 3.6 汇报与决策支撑

+   向 CIO 提供 BCM 成熟度评估报告，内容应反映当前能力水平与目标之间的差距，不止于罗列已完成的演练次数。
+   真实应急事件中，安全管理团队作为科技侧指挥协调角色：判断事件等级，决定是否启动应急响应或向上升级，统筹对外通报；运维团队负责具体技术操作。
+   重大 BCM 决策（如灾备中心建设、核心系统双活改造）向 CIO 提供差距分析和方案建议。

# 4 运维团队的职责

+   运维团队承担科技侧 BCM 的全部技术执行工作，具体包括：

    -   编制各系统的应急预案和操作手册
    -   制定灾备演练计划，设计演练场景，组织演练执行
    -   执行灾备切换、系统恢复等技术操作
    -   日常备份管理和基础设施连续性保障
    -   向风险管理部主导的 BIA 提供系统技术参数（关键系统清单、依赖关系、建议 RTO/RPO）
    -   向安全管理团队提供现状数据，配合差距评估和鉴证工作
    -   根据安全管理团队提出的目标要求，制定技术实施方案并提交审核
    -   执行经审核通过的技术改造任务

# 5 职责边界

+   安全管理团队与运维团队的职责边界按四项权力划分：

    -   **评估权归安全管理团队**：BCM 现状差距分析（基于风险管理部 BIA 成果）、成熟度评估，由安全管理团队主导，运维团队提供技术数据输入
    -   **规划权归运维团队**：灾备架构设计、演练场景编排、恢复流程优化等技术实施方案，由运维团队制定；安全管理团队审核方案是否满足目标，不介入技术方案本身的设计
    -   **鉴证权归安全管理团队**：演练效果由安全管理团队独立鉴证，运维团队不得以自评报告替代
    -   **执行权归运维团队**：所有技术操作（灾备切换、系统恢复、演练执行）由运维团队完成

+   职责边界一句话：**安全管理团队负责判断"够不够、对不对、下一步往哪走"；运维团队负责"怎么做、做到位"。**

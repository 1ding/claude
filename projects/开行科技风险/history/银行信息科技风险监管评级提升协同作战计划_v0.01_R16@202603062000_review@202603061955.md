## 1.2 逻辑一致性

+   **评分：3/5**

### 1.2.1 主要发现

1.   **主线逻辑总体清晰**：从"现状基础已具备"推导出"重点不是建设而是深化"，再映射到十大战役，整体叙事是自洽的。
2.   **存在若干明显前后不一致**：
    -   **战役七牵头部门不一致**：
        -   第一章映射表写"信息科技部·风险管理"；
        -   第一章内部板块分工写"信息科技部·应用支持主责战役七"；
        -   第五章战役七又写"信息科技部·网络安全（供应链安全评估）"。
        -   这是全篇最明显的责任归属冲突。
    -   **D8映射与原则表述不完全一致**：原则说"每个评级维度都有且仅有一个主责战役"，但D8又写成"独立保障机制（贯穿全计划）"，并非战役。
    -   **年度目标前后倒挂**：战役六中，2026年验收写"RTO/RPO 100%达标"，但2027年目标反而是"≥90%"，存在阶段性倒退。
    -   **战役二目标进阶不明显**：2026、2027均写"KRI自动采集≥80%"，年度演进逻辑偏弱。
    -   **战役八与战役二在监管报送接口上的边界不清**：2026年已提出"自动化报送系统上线运行"，2029年又提出"实时自动报送接口上线"，两者关系未定义清楚。
3.   **治理角色存在边界模糊**：
    -   文中将"信息科技部·风险管理"定义为第一道防线，同时又承担计划办公室、问题清单发起、风险评估、KRI治理等职责，容易与第二道防线的风险管理部门形成职能交叉。
    -   审计部既被强调独立，又被设置为销号的唯一验证者，存在"独立监督"与"嵌入日常管理闭环"之间的张力。

### 1.2.2 具体建议

1.   **统一战役七责任归属**：明确"谁总体牵头、谁专业主建、谁协同"，并全篇一次性改统一。
2.   **重写D8口径**：建议改为"D8对应独立审计主线，不纳入战役执行体系，但设单独审计计划与交付物"，避免与"一个维度一个战役"冲突。
3.   **修正年度目标递进关系**：尤其是战役二、六、八，确保每年目标不是重复或倒退。
4.   **明确"自动化报送"与"实时直连监管"的层级关系**：例如定义为"2026内部自动校验报送、2029在监管条件具备前提下实现接口化/准实时化"。
5.   **重新梳理三道防线职责边界**：建议增加一张RACI矩阵，明确一/二/三道防线在"制定标准、执行、监测、验证、销号"中的责任。

## 1.3 专业准确性

+   **评分：3/5**

### 1.3.1 主要发现

2.   **监管引用需系统校核**：

    -   例如：正文第二章写《银行保险机构信息科技外包风险监管办法》（2022），附录又写"银保监办发〔2021〕141号"，口径不一致。

3.   **部分术语使用不够严谨**：
    -   **CMMI通常表述为"评估/鉴定"而非"认证"**。
    -   **"密评（GB/T 39786—2021）"的表述过于简化**，建议核验密评所对应的具体标准体系，避免把"密码应用基本要求"直接等同于"商用密码应用安全性评估"。
4.   **预测性内容表述过于确定**：
    -   第二章把若干AI监管、算法审计、AI伦理委员会等内容写成"高度确定"或近似既成趋势，专业上应区分"已发文要求""高概率研判""前瞻假设"。
5.   **部分控制要求过于绝对化，缺少例外机制**：

6.   **部分量化指标缺少监管/制度依据**：
    -   "维度覆盖率≥90%""集中度≤50%""安全产品核心功能启用率≥80%""P1级30分钟响应"等，需要标明这是**监管要求、内部管理目标，还是行业最佳实践目标**。

### 1.3.2 具体建议

1.   **做一次法规与标准总校核**：逐条核验正式名称、发文机关、文号、年份、效力层级。
2.   **区分"强制要求"与"内部拔高目标"**：建议在附录二增加"性质"列（监管硬约束/内部提升项/前瞻储备项）。
3.   **修正专业术语**：如CMMI、密评、EAST、RCSA、SBOM等，首次出现时建议给出规范全称或定义。
4.   **把预测改为情景化表达**：例如分"高确定性/中确定性/观察项"三级，而不是统一写"高度确定"。
5.   **为刚性指标增加例外管理机制**：避免执行中因"一刀切"导致制度名义完美、实际不可执行。

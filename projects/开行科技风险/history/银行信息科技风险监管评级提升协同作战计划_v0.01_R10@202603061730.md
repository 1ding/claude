# 银行信息科技风险监管评级提升协同作战计划（2026—2030）

# 第一章 总则

## （一）制定目的

+   本计划面向2026—2030年五年周期，以"超越底线、质量优先、深化落地、协同作战"为核心，在现有制度框架与平台基础上，系统提升信息科技风险管理的实质有效性，推动监管评级持续改善。
+   **核心问题诊断**：当前本行信息科技风险管理的核心矛盾不在于"有没有"，而在于"好不好"与"真没有"——一方面，ITIL/ISMS/等保/密评/核心制度/运营平台等基础框架已具备（详见本章"现状基础"），但整体存在**底线思维过重**的全面性问题：各项工作以满足监管最低要求为隐性目标，制度与执行脱节，游走于合规边缘；另一方面，**数据治理层面真正欠缺**，数据资产目录、数据分类分级等基础性工作尚未真正落地，成为评级提升的突出短板。
+   **底线思维的评级影响**：本行内部自评认为，当前各评级维度的总体状态是"维度均有覆盖，执行多在边缘"——底线思维足以保住基本分、避免明显失分，但在各维度上缺乏显著高于监管基准的质量优势，导致评级难以实现跨档提升。要从"基本合格"走向"优良"，必须在各维度上建立起超越底线的质量厚度。
+   **2026年核心目标**：严格对照《商业银行信息科技风险管理指引》八大评级维度，以"深化落地、提升实质有效性、补齐数据治理缺口"为主线，聚焦监管高频扣分项，推动评级从[当前级别]提升至[目标级别]，信息科技风险得分提升10%以上，助力全行综合监管评级升级。
+   **五年战略目标**：至2030年，监管评级稳定保持优良等级，建立可持续运转的科技风险治理长效机制，实现从"底线合规"向"卓越治理"的根本转变，达到政策性银行同业先进水平。

## （二）现状基础

+   本行信息科技风险管理已具备以下基础能力，本计划以此为起点推进深化与提升，而非重复建设：

    | 基础领域           | 现状描述                                                                 | 状态   |
    | ------------------ | ------------------------------------------------------------------------ | ------ |
    | IT服务管理框架     | ITIL/ISO 20000体系已实施，ITMIS平台（含事件、变更、配置管理模块）运行中 | 已落地 |
    | 信息安全管理体系   | ISMS/ISO 27001已通过认证，安全制度体系已建立                             | 已认证 |
    | 等级保护测评       | 重要系统已完成等保2.0测评并通过                                          | 已通过 |
    | 密码测评           | 核心系统已完成商用密码应用安全性评估（密评）                             | 已通过 |
    | 核心制度           | 信息科技风险管理办法、外包管理办法等必要制度已发布生效                   | 已建立 |
    | 安全运营与监控平台 | ITMIS、SOC等运维与安全运营平台已部署上线                                 | 已上线 |
    | 软件开发成熟度     | CMMi 已通过认证（软件开发能力成熟度基础已具备）                          | 已认证 |

+   **现状的核心问题**：上述基础框架主要解决了"有没有"的问题，但在执行深度和实质有效性上普遍存在**底线思维**：等保/密评重在通过而非整改落地，制度存在但执行合规率未被有效追踪，ITMIS数据质量和KRI自动采集率有待提升，各领域普遍游走于合规边缘。与此同时，**数据治理层面是真正的空白**：数据资产目录、数据分类分级尚未系统落地（对应战役八）。

## （三）核心原则

-   **超越底线，质量优先**：拒绝以满足监管最低要求为隐性目标，以"实质有效"而非"形式达标"为交付标准；所有战役的任务动词优先采用"深化、提升、落地"，而非"建设、新增、发布"；已有基础上的质量提升，比重复建设更重要。
-   **填坑有序，亮点有意**：真正需要从零补齐的"坑"并不多（主要集中在2026年），不应将一般性深化与提升混同为填坑；亮点不能靠堆砌数量，须每年有意识地选定方向集中投入，形成显著优于监管基准的质量优势；填坑保住基本分，亮点才能推动评级跨档提升。
-   **对标监管，全量覆盖**：以《商业银行信息科技风险管理指引》八大评级维度为基准坐标系，建立"评级维度—战役—任务—交付物"的四级映射关系，确保每个评级维度都有且仅有一个主责战役，不留覆盖盲区。
-   **协同联动，打破壁垒**：以三大核心协作机制为抓手，推动信息科技部各专业板块与风险管理、审计部、数据管理部及业务部门高效联动，形成协同作战格局。
-   **务实落地，量化可考**：所有战役任务明确"牵头板块/部门+协同部门+交付物+量化验收标准+完成时限"，每项工作均有具体动作、可穿透验证的量化标准和证据要求。
-   **机制兜底，闭环管控**：以"整改销号"机制为保障，强化审计独立验证，形成"发现—认领—整改—验证—销号"全闭环。
-   **聚焦提升，证据先行**：优先启动需要长周期积累执行记录的维度（开发测试管理、运行管理），确保迎检时有充足、连续的过程证据链。
-   **跟踪监管，动态优化**：以年度复盘和监管政策跟踪为驱动，滚动调整各年度目标，确保计划始终对准监管前沿（参见第二章监管趋势预测）。

# 第二章 监管趋势预测与五年计划依据

+   本章系统梳理五年计划期内的监管政策演进趋势，作为各阶段重点工作安排的依据。监管预测基于现行政策脉络分析，实际政策以监管机构正式发文为准，计划每年复盘时根据新发政策滚动调整。

## （一）现行监管框架要点

+   当前信息科技风险监管的核心依据体系如下，构成五年计划的基准约束：

    | 监管层级 | 核心文件                                         | 主要约束方向                     |
    | -------- | ------------------------------------------------ | -------------------------------- |
    | 国家法律 | 《网络安全法》《数据安全法》《个人信息保护法》   | 数据安全、网络运行安全的法律底线 |
    | 行政法规 | 《关键信息基础设施安全保护条例》（2021）         | 关基运营者安全保护义务           |
    | 部门规章 | 《商业银行信息科技风险管理指引》（2009）         | IT治理三道防线、八大评级维度     |

## （二）2026年近期监管动向

+   以下政策动向高度确定，直接影响本计划2026年战役的工作重点：

    -   **《金融科技发展规划（2026—2030年）》**：现行2022-2025年规划到期，新一轮五年规划预计2026年发布，将明确"人工智能+"深度应用、数据资产价值释放等方向，直接驱动本计划后续阶段的战略重点。
    -   **AI算法风险专项监管**：2025年AI算法风险已成监管核心关注点，大模型备案管理要求、算法审计纳入信息科技审计范围等动作预计在2025-2026年陆续落地；金融领域AI模型风险管理专项指引有望出台。
    -   **数据安全双规落地**：金监总局数据安全办法（金规〔2024〕24号，2024年12月施行）和人民银行数据安全办法（2025年6月施行）相继落地，2026年是执法检查的关键之年，数据分类分级、敏感数据目录将是检查重点。
    -   **《商业银行信息科技风险管理指引》修订压力**：该文件历经15年未作整体修订，修订方向预期增加AI治理专章、数据资产化框架和第三方风险章节，2026年后存在修订可能。

## （三）2027—2028年中期趋势

+   以下趋势对本计划第二、三阶段工作安排有重要影响：

    -   **AI算法审计常态化**：AI算法审计有望成为信息科技审计的常规检查项，银行需建立算法模型全生命周期管理制度和可解释性保障机制。
    -   **密评覆盖率要求提升**：密评覆盖范围向重要业务系统扩展，核心系统密评覆盖率将成为现场检查重要指标。
    -   **数字金融能力评估**：监管对银行AI应用、数据资产、云原生架构等数字金融能力的评估要求提升，科技投入产出比将纳入综合评价视野。

## （四）2029—2030年长期趋势

+   以下长期趋势影响本计划第四、五阶段的工作方向：

    -   **实时监管与穿透监管全面建成**：EAST系统向实时、准实时数据采集演进，监管机构的非现场监测能力大幅提升，银行需具备监管数据自动采集、实时校验和接口对接能力。
    -   **AI伦理治理框架成熟**：AI伦理委员会将成为银行标配治理架构，算法公平性、可解释性、数据偏见防范成为常规合规要求。
    -   **数据资产化体系完善**：数据资产入表配套实施细则落地，金融数据流通交易规则明确，银行数据资产管理能力将面临全面评估。

# 第三章 核心协作机制

## （一）"科技风险联防联控委员会"（决策与协调层）

+   **定位**：全行科技风险管理的最高议事协调机构，核心解决"定方向、给资源、判争议"的关键问题，确保评级提升工作高位推动。

+   **组织架构**：

    -   组长：分管科技的副行长（建议由行长直接授权），首席风险官（CRO）任副组长
    -   成员：信息科技部（部长及五个专业板块负责人）、风险管理、数据管理部、合规部负责人
    -   审计部**列席**（保留知情权和建议权，不参与表决，以保障审计独立性）
    -   业务部门代表按议题需要列席
    -   常设办公室：设在信息科技部·风险管理，负责日常督办、进度汇总、会议组织

+   **运行频率**：

    -   月度例会：通报十大战役进度，协调跨部门资源冲突，解决执行难题
    -   季度汇报：向董事会及其风险管理委员会专题汇报评级提升进展，同步监管要求
    -   年度复盘：每年12月开展五年计划年度复盘，结合监管新政滚动调整下一年计划
    -   紧急会议：发生重大科技安全事件或监管政策重大调整时，24小时内召开专题会议

+   **核心职能**：

    -   批准年度战役目标及资源方案，每年滚动审定五年计划调整
    -   裁决争议：当各专业板块与风险管理在"风险定级""整改优先级"或"业务上线阻断"上发生分歧时，拥有最终裁决权
    -   批准专项预算和跨部门人力借调
    -   应急权限：当评级期内发生重大风险事件时，有权调整战役优先级，启动计划降级预案

## （二）"风险—科技—数据"三角联席工作制（执行与落地层）

+   **定位**：针对具体业务场景的标准化作业流程，解决"事前谁定标、事中谁监控、事后谁评价"的落地难题。

+   **适用场景**：重大系统上线、新业务投产、监管新规落地、新技术（AI/云）应用、核心数据变更等关键场景。

+   **运作模式（三方会签制）**：

    -   事前（准入关）：数据管理部定义数据标准、分类分级及隐私保护策略；信息科技部制定技术架构与安全设计；风险管理审核合规性与残余风险。三方会签后方可立项/上线（缺一不可）
    -   事中（监控关）：信息科技部·系统运行负责系统稳定与基础设施保障；信息科技部·网络安全负责攻击防御与威胁监测；信息科技部·风险管理监测KRI指标，触发阈值即启动预警
    -   事后（评价关）：审计部独立开展后评价审计，结果直接反馈至联防联控委员会

+   **业务部门参与机制**：涉及业务影响分析（BIA）、业务连续性演练、数据Owner确认等场景时，相关业务部门须作为第四方参与会签或确认。

## （三）"问题整改销号"闭环机制（监督与问责层）

+   **定位**：确保所有发现的问题"真改、实改"，为评级提升筑牢监督防线。

+   **管理工具**：搭建统一的"监管评级提升任务管理平台"（数字化看板），实现任务认领、进度跟踪、验证销号全线上化。

+   **强制流程**：

    -   发起：信息科技部·风险管理基于自评、监管提示或内外部检查，生成《问题整改清单》，明确责任板块/部门、整改标准及时限
    -   认领：责任部门在3个工作日内认领任务，制定具体整改措施和完成时限（SLA）
    -   验证：审计部通过非现场数据分析+现场穿透测试进行独立验证
    -   销号：仅当审计部出具"验证通过"意见后方可执行销号

+   **红线原则**：未通过审计验证的问题，严禁销号；逾期未完成的，自动升级至联防联控委员会督办，直接与部门及板块绩效考核挂钩。

## （四）IT审计独立性保障机制（对应D8评级维度）

+   **角色边界**：

    -   审计部**不参与**联防联控委员会的决策表决，仅列席
    -   审计部**不参与**三角联席的事前会签和事中监控，仅在事后独立评价
    -   审计部**不参与**整改标准的制定，仅负责整改结果的独立验证
    -   审计部有权对任何战役整改成效提出独立质疑，不受联防联控委员会决议约束

+   **审计工作体系**：

    -   每年Q1制定《信息科技审计年度计划》，覆盖十大战役涉及的全部评级维度
    -   编制三年滚动IT审计计划，确保所有关键IT领域在三年内至少接受一次全面审计
    -   全年开展不少于3次专项审计（Q2/Q3各1次过程审计，Q4开展"整改回头看"全面审计）
    -   对高风险领域（信息安全、业务连续性）聘请具备资质的外部审计机构进行独立复核

### 战役二：IT风险管理体系深化（全力攻坚·亮点）

+   **职责分工**：牵头：信息科技部·网络安全；协同：信息科技部·风险管理、风险管理、数据管理部、合规部

# 第十章 应急调整机制

## （一）计划降级预案

+   当评级期内发生以下重大冲击时，联防联控委员会有权启动计划降级：

    | 触发场景                          | 应急响应                                                     | 资源调整                       |
    | --------------------------------- | ------------------------------------------------------------ | ------------------------------ |
    | 重大信息安全事件（数据泄露/勒索） | 24小时内召开紧急会议，暂停非核心战役，资源集中处置与根因整改 | 战役九、十降级为维持性任务     |
    | 监管专项检查/突击检查             | 48小时内成立专项应对小组，对检查涉及维度优先完善证据链       | 根据检查范围动态调整战役优先级 |
    | 关键供应商重大事故                | 启动外包退出应急预案，评估对灾备和运行的影响                 | 战役七升级为最高优先级         |
    | 监管评级标准重大调整              | 一周内完成新标准与十大战役映射分析，调整覆盖方案             | 视影响范围新增或调整战役内容   |

## （二）优先级保底原则

+   无论发生何种冲击，以下"保底四战役"的执行不得中断：

-   战役三（信息安全）——一级关注领域，直接决定评级底线
-   战役四（开发测试）——证据链不可中断，一旦断裂无法补救
-   战役五（运行管理）——证据链不可中断，一旦断裂无法补救
-   战役六（业务连续性）——一级关注领域，直接决定评级底线

# 第十一章 保障措施

## （一）组织保障

+   联防联控委员会统筹全局，每月召开推进会；常设办公室（信息科技部·风险管理）负责日常督办，每周汇总各专业板块进展；各战役"特战队"明确牵头人，确保执行到位。各业务部门指定固定联络人参与BIA、数据Owner确认等协同工作。

## （二）资源保障

+   专项整改预算优先保障，重点用于安全能力提升工具、CMDB/ITMIS平台升级、SAST/DAST工具采购、第三方审计/测试、信创替代持续投入等；人力资源部优先落实关键岗位招聘和双向挂职计划；跨部门人力借调由联防联控委员会统一审批。

+   五年预算规划原则：

-   刚性优先保障：灾备建设、安全运营、监管合规相关投入不得以预算压缩为由延期
-   年度滚动预算：依据当年评估结论动态调整投入重点
-   四类投入：工具平台采购与建设、系统改造升级、外部咨询与审计、人员培训与认证

## （三）考核与激励

-   **双向打分制**：信息科技部（含各专业板块）绩效，30%由风险管理打分；风险管理绩效，20%由信息科技部打分；审计部绩效由审计委员会独立评价，不纳入双向打分
-   **红线问责**：因部门推诿导致评级下降或发生重大风险事件的，部门负责人年度绩效一票否决；审计验证发现"虚假整改"的，直接移交纪检监察部门处理
-   **激励机制**：对战役攻坚成效显著、按时完成任务的板块和个人，给予绩效加分和评优表彰

## （四）沟通联动保障

+   主动对接监管机构，及时了解最新监管评级要求，主动汇报工作进展；发生重大科技事件须按监管要求时限完成事件报告；加强政策性银行同业交流，借鉴先进经验为后续年度计划提供参考。

# 第十二章 附则

+   本计划自发布之日起实施，由科技风险联防联控委员会负责解释。各部门及专业板块需根据本计划制定具体实施细则，确保任务落地到岗、责任到人。
+   本计划每年12月由联防联控委员会组织年度复盘，结合监管政策变化和战役推进情况，适时调整优化五年路线图和年度重点工作。

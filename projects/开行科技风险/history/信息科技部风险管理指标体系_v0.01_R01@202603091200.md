# 第一部分 总体设计

## 1.1 设计原则

+   本指标体系服务于《银行信息科技风险监管评级提升协同作战计划（2026—2030）》战役二"IT风险管理体系深化"的年度目标：2026年底 KRI 指标数量 ≥ 30 个，自动采集覆盖率 ≥ 60%。
+   指标设计遵循以下原则：

-   **领先优先**：优先设置领先指标（预警潜在风险），减少仅反映已发生问题的滞后指标；领先指标在全体系中占比目标 ≥ 50%
-   **可量化、可穿透**：所有指标须有明确的数据来源和采集路径，不接受主观打分和估算值
-   **自动化导向**：标注每项指标的采集方式，制定向自动采集迁移的路线；2026年底自动+半自动合计 ≥ 60%
-   **阈值三档**：绿（优于监管基准）/ 黄（仅满足监管最低要求）/ 红（低于监管最低要求）——详见 1.4 节
-   **效果优于形式**：关键指标须同时测量"做没做"（过程）和"有没有效"（结果），防止仅追求报告完成而忽视实质改进

## 1.2 指标类型与采集方式

| 类型 | 含义                                             | 示例                        |
| ---- | ------------------------------------------------ | --------------------------- |
| 领先 | 预测性指标，指向未来可能发生的风险，用于提前预警 | CMDB准确率、基线覆盖率      |
| 滞后 | 结果性指标，反映已发生事件的处置质量             | RCA完成率、漏洞修复周期     |
| 过程 | 执行进度指标，用于追踪战役任务的落地情况         | DevSecOps覆盖率、演练场景数 |

| 采集方式 | 定义                           | 2026年自动化目标   |
| -------- | ------------------------------ | ------------------ |
| 自动     | 系统自动抓取，无需人工录入     | 维持               |
| 半自动   | 系统提供原始数据，人工汇总计算 | 逐步迁移至全自动   |
| 人工     | 完全依赖人工收集、录入         | 制定自动化改造计划 |

## 1.4 阈值设计哲学——突破底线思维

+   **核心原则**：绿色（正常）门槛设定于监管基准之上；仅满足监管最低要求属于黄色（预警），不得视为合格状态。本设计的意图是从制度上消除"过了底线就不用动"的心理预期。

| 状态       | 含义                                       | 行动要求                                    |
| ---------- | ------------------------------------------ | ------------------------------------------- |
| 绿（正常） | 指标值明显优于监管基准，体现超越底线的质量 | 保持并总结经验；季度通报推广                |
| 黄（预警） | 指标值接近或仅满足监管最低要求             | 制定提升计划，下季度目标达绿；不得超过2季度 |
| 红（告警） | 指标值低于监管最低要求                     | 5个工作日内提交整改计划至风险管理-制度处    |

+   **黄色状态不等于安全**：处于黄色状态超过2个连续季度的指标，牵头板块负责人须向科委会专项说明。

# 第四部分 指标管理与维护要求

## D1 指标更新机制

-   **年度复盘**：每年12月，由风险管理-制度处牵头，各板块联合评审指标有效性；增删调整须经风险管理部会签后报科委会备案
-   **阈值年度收紧**：对标突破底线思维的设计原则，各板块每年评估是否可将绿区门槛进一步提升，形成持续进步机制
-   **临时调整**：重大监管政策变化或重大风险事件发生后，风险管理-制度处可发起临时调整，须在30天内完成修订并记录

## D2 数据质量管理

-   月度指标：次月5日前完成填报；季度指标：季后10日前完成填报
-   人工采集指标须附原始数据来源截图或台账编号，不接受估算值
-   风险管理-制度处每季度对各板块数据质量进行抽查，抽查结果纳入板块绩效考核
-   **反虚报机制**：审计部每半年对随机抽取的5个指标进行穿透核查，核查结果与绩效考核直接挂钩

## D3 阈值调整规则

-   **单向原则**：阈值只能收紧（绿区提升），不得放宽，除非监管政策变化有明确要求
-   **红线指标**（IT-RM-02、IT-RM-06、IT-AS-03、IT-RG-01、IT-TR-01、IT-TR-03）：阈值不得放宽，永久保持零容忍
-   **参照系**：阈值调整须参照当年监管最新要求和同业先进水平，确保绿区始终领先于监管基线

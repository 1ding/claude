## 2 执行摘要

+   本计划面向2026—2030年，系统谋划信息科技风险监管评级提升路径，以"夯基础、补短板、强能力、创卓越"为主线，分五阶段推进。
+   计划覆盖信息科技部五个核心职能板块：系统运行（含基础设施）、应用支持、开发测试、安全、风险管理，形成纵向联动、横向协同的矩阵化作战格局。
+   最终目标：至2030年，信息科技风险监管评级达到优良等级，关键领域达到政策性银行同业领先水平，建立可持续运转的科技风险治理长效机制。

## 3 监管背景与评级框架

### 3.1 政策依据

+   主要依据以下监管规范性文件：

-   《银行业金融机构信息科技监管评级指引》
-   《商业银行信息科技风险管理指引》（银监发〔2009〕19号）
-   《银行保险机构信息科技外包风险监管办法》
-   《网络安全法》《数据安全法》《个人信息保护法》
-   金融监管总局历年科技监管检查要点通报及监管处罚案例

### 3.2 评级维度与部门分工

+   监管评级通常从以下八个维度综合评定，各维度主责部门如下：

    | 评级维度         | 主要考察内容                           | 主责部门           |
    | ---------------- | -------------------------------------- | ------------------ |
    | 信息科技治理     | 组织架构、职责分工、资源投入、文化建设 | 风险管理、全部门   |
    | 基础设施管理     | 机房、网络、服务器、容量管理、变更管理 | 系统运行           |
    | 应用系统管理     | 需求、开发、测试、上线、运维全生命周期 | 应用支持、开发测试 |
    | 数据管理         | 数据质量、数据安全、数据分类分级治理   | 安全、应用支持     |
    | 网络安全管理     | 访问控制、漏洞管理、安全监控、应急响应 | 安全               |
    | 业务连续性管理   | 灾备建设、应急演练、RTO/RPO目标达成    | 系统运行、风险管理 |
    | 科技风险管理     | 风险识别、评估、监测、报告、三道防线   | 风险管理           |
    | 信息科技外包管理 | 准入审核、合同规范、持续监督、退出管理 | 风险管理、应用支持 |

### 3.3 当前主要差距判断

+   结合监管检查共性问题与行业高频处罚领域，重点关注以下典型短板：

-   科技风险三道防线职责边界模糊，科技风险未有效内嵌业务流程
-   变更管理流程不规范，变更引发故障占比偏高
-   灾备演练覆盖度不足，RTO/RPO未经充分验证或实际不达标
-   安全开发规范落地不到位，系统上线前安全测试缺失或流于形式
-   数据分类分级管理尚未系统化，敏感数据防护存在盲区
-   外包厂商管理粗放，关键外包依赖度高、退出机制缺失或不可执行
-   科技风险量化评估能力薄弱，难以支撑管理层决策

## 4 五年战略路径

+   五年计划按照"打好基础—补齐短板—体系成熟—数字赋能—卓越引领"的演进逻辑分阶段推进：

    ```graph
    2026              2027              2028              2029              2030
    ┌──────────┐      ┌──────────┐      ┌──────────┐      ┌──────────┐      ┌──────────┐
    │ 夯实基础 │ ───▶ │ 补齐短板 │ ───▶ │ 体系成熟 │ ───▶ │ 数字赋能 │ ───▶ │ 卓越引领 │
    │ 摸清底数 │      │ 完善制度 │      │ 提质增效 │      │ 智能管控 │      │ 行业标杆 │
    └──────────┘      └──────────┘      └──────────┘      └──────────┘      └──────────┘
    ```

### 4.1 第一阶段（2026）：夯实基础·摸清底数

+   核心目标：完成全域现状评估，识别关键差距，建立治理基础，启动高优先级整改。

+   **重点工作：**

    -   开展信息科技风险全面自评估，对标监管评级八大维度形成差距清单与整改优先级矩阵
    -   成立信息科技风险管理委员会，明确三道防线职责边界，制定配套制度
    -   制定五年整改路线图，分解至各二级部门，确立年度关键成果（OKR）
    -   推动ITIL核心流程（变更、事件、问题管理）落地，建立流程基准数据
    -   开展灾备现状普查，评估关键系统灾备覆盖率与RTO/RPO现状
    -   建立统一的科技风险关键指标（KRI）体系框架

+   **年度里程碑：**

    -   差距评估报告发布，优先级整改清单经委员会审定
    -   信息科技风险管理委员会正式成立并完成首次例会
    -   ITIL变更/事件/问题管理制度正式发布实施

### 4.2 第二阶段（2027）：补齐短板·完善体系

+   核心目标：系统性补足监管高频关注的重点短板，各管理体系实现制度化、流程化。

+   **重点工作：**

    -   发布安全开发生命周期规范（SDL），引入静态/动态代码安全扫描工具（SAST/DAST）
    -   建立数据分类分级管理体系，完成全行数据资产梳理与目录建设
    -   发布外包管理规范，规范准入—合同—监督—退出全生命周期管理
    -   完成灾备建设重点整改，关键业务系统灾备覆盖率提升至100%
    -   上线需求管理平台，规范需求受理、评估、优先级排序全流程
    -   建立月度科技风险报告与定期监管报送机制

+   **年度里程碑：**

    -   SDL规范正式上线，全部新建系统纳入SDL管控
    -   数据资产目录完成，数据分类分级规则经审定发布
    -   关键系统灾备演练覆盖率 ≥ 80%，RTO/RPO验证达标

### 4.3 第三阶段（2028）：提质增效·体系成熟

+   核心目标：管理体系全面成熟，自动化工具覆盖主要管控领域，争取监管评级显著提升。

+   **重点工作：**

    -   推进DevSecOps转型，将安全检测能力嵌入CI/CD流水线（安全左移）
    -   建立科技风险全景地图，实现风险状态动态可视化与预警
    -   完善业务连续性管理（BCM）体系，年度全面演练制度化常态化
    -   推进基础设施巡检自动化，容量管理引入趋势预测与智能预警
    -   建立外包商绩效量化评估体系，推动关键外包集中管控
    -   组织内部监管模拟检查，查漏补缺，形成检查整改闭环机制

+   **年度里程碑：**

    -   DevSecOps流水线覆盖主要开发项目（覆盖率 ≥ 60%）
    -   科技风险全景地图上线，动态更新机制建立
    -   年度监管模拟检查整改完成率 ≥ 95%

### 4.4 第四阶段（2029）：数字赋能·智能管控

+   核心目标：以AI/大数据技术赋能风险管理能力，实现从被动响应向主动预防的跨越。

+   **重点工作：**

    -   建设安全运营中心（SOC），部署SIEM/SOAR平台，实现威胁自动检测与响应
    -   引入用户实体行为分析（UEBA），提升内部风险与异常行为感知能力
    -   推进智能运维（AIOps）平台建设，降低故障均值恢复时间（MTTR）
    -   构建科技风险量化评估模型，支持主要风险类别的量化计量与压力测试
    -   完善监管数字化报送体系，实现监管数据自动采集、校验与报送

+   **年度里程碑：**

    -   SOC正式上线，威胁检测响应时效较基准缩短50%
    -   AIOps覆盖核心生产系统，MTTR较2026年基准降低40%
    -   风险量化模型覆盖主要风险类别

### 4.5 第五阶段（2030）：卓越引领·持续发展

+   核心目标：确立政策性银行科技风险管理标杆地位，建立可持续改进的长效治理机制。

+   **重点工作：**

    -   完成五年整改成果系统性复盘，组织科技风险管理成熟度评估（对标CMM框架）
    -   推进零信任安全架构试点落地，构建下一代身份与访问控制体系
    -   探索科技风险与业务韧性、数字化转型战略的协同融合路径
    -   建立科技风险管理持续改进（PDCA）长效机制，固化制度与工具体系
    -   参与行业交流，输出开行科技风险管理最佳实践与经验

+   **年度里程碑：**

    -   监管评级达到优良等级并稳定保持
    -   科技风险管理成熟度达到行业先进水平（CMM Level 4 及以上）
    -   最佳实践文档化，参与2家以上行业交流或监管专题研讨

### 6.2 常态联动机制

+   **月度科技风险例会**：各部门汇报KRI达成情况与重大风险事项，风险管理部汇总形成月度科技风险报告，提交委员会审阅。
+   **重大变更联审**：涉及生产环境的重大变更须经系统运行、开发测试、安全、风险管理部联合评审方可实施。
+   **安全事件应急联动**：安全部触发应急响应后，系统运行、应用支持、开发测试协同处置，风险管理部同步完成监管报告。
+   **年度自评估协同**：风险管理部牵头组织，各部门配合完成监管评级对标自评估，共同制定差距整改清单。
+   **季度内审协同**：配合审计部开展科技审计，提供过程证据，推动审计发现整改闭环。

### 6.3 外部协同要求

+   **监管部门**：配合现场检查、按时报送定期报告、及时响应监管函件，统一由风险管理部对口协调；发生重大科技事件须按监管要求时限完成事件报告。
+   **合规/内控**：科技风险管理纳入全行风险管理框架，与合规风险、操作风险管理有机衔接，避免重复建设与管理盲区。
+   **业务条线**：应用支持部作为主要接口，将业务需求引发的科技风险纳入前置评估；高风险新业务上线须经科技风险评审。

## 7 关键绩效指标体系（KRI/KPI）

+   以下指标作为五年评级提升进度的核心衡量依据，2026年以建立基准值为重点，后续年度逐步收紧目标：

    | 指标类别   | 指标名称                   | 2026基准 | 2028目标      | 2030目标      |
    | ---------- | -------------------------- | -------- | ------------- | ------------- |
    | 系统可用性 | 核心系统年度可用率         | 建立基准 | ≥ 99.95%      | ≥ 99.99%      |
    | 变更管理   | 生产变更成功率             | 建立基准 | ≥ 97%         | ≥ 99%         |

## 8 资源保障

### 8.1 组织保障

-   信息科技风险管理委员会作为最高决策机构，由行领导担任主任，信息科技部主要负责人任常务副主任
-   信息科技部统筹牵头，风险管理部负责计划整体跟踪与协调
-   各二级部门设立兼职科技风险联络员，负责本部门年度计划日常推进与KRI数据报送

### 8.2 人员能力建设

-   制定科技风险管理专项培训计划，涵盖监管政策解读、风险管理方法论、技术工具实操三个维度
-   重点岗位支持取得CISA、CISSP、CRISC等国际专业认证，纳入绩效激励
-   建立内部专家讲师团队，定期开展案例教学，推动外部监管经验向内部知识转化

### 8.3 预算规划原则

-   五年总投入规划涵盖四类：工具平台采购与建设、系统改造升级、外部咨询与审计、人员培训与认证
-   实行年度滚动预算，依据当年评估结论动态调整投入重点与优先级
-   刚性优先保障：灾备建设、安全运营、监管合规相关投入不得以预算压缩为由延期

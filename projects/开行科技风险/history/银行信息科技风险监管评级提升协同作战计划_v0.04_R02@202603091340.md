# 银行信息科技风险监管评级提升协同作战计划（2026—2030）

# 第一章 综述

## （一）制定目的与目标

+   本计划面向2026—2030年五年周期，以"超越底线、质量优先、深化落地、协同作战"为核心，在现有制度框架与平台基础上，系统提升信息科技风险管理的实质有效性，推动监管评级持续改善。
+   **2026年核心目标**：严格对照《商业银行信息科技风险管理指引》八大评级维度，以"深化落地、提升实质有效性、全面提升质量标尺"为主线，聚焦监管高频扣分项，推动评级从[当前级别]提升至[目标级别]，信息科技风险得分提升[目标分值]以上，助力全行综合监管评级升级。
+   **五年战略目标**：至2030年，监管评级稳定保持优良等级，建立可持续运转的科技风险治理长效机制，实现从"底线合规"向"高质量治理"的持续转变，力争达到[政策性银行同业先进水平]。

## （二）方案整体逻辑与摘要

+   本方案的立论起点是两个判断：其一，本行信息科技风险管理的核心矛盾不在于"有没有"，而在于**底线思维过重**——各项工作以满足监管最低要求为隐性目标，合规水平普遍接近监管底线（详见第二章）；其二，存在少量缺口， 如**数据治理层面**，数据资产目录、数据分类分级等基础工作尚未落地[有待核实，据我们所知2025年还没落实到系统层面]。
+   基于上述诊断与监管趋势分析（第三章），本方案确立"超越底线、质量优先"等核心原则（第四章），并将八大监管评级维度映射为**十大战役**，按强度分层推进：每年选定1—2个方向集中投入形成重点突破，其余战役以底线保障或深化维护为定位，确保全维度覆盖的同时实现重点跨档提升。十大战役的完整框架定义见第五章。
+   五年演进分为五个阶段：2026年夯实基础、攻坚评级（第六章），2027年深化体系（第七章），2028年争创优良（第八章），2029年数字赋能（第九章），2030年持续优化与长效治理（第十章）。
+   在组织保障层面，各年度作战计划中的部门分工基于全行既有职责定位；第十一章对各部门在本计划中的角色做显式汇总，并定义"风险—科技—数据"三角联席等专项协作机制，为跨部门协同提供制度支撑。保障措施与应急调整机制见第十二章。

## （三）适用范围

+   覆盖全行各部门、各分支机构。核心聚焦信息科技部（含五个专业板块）、风险管理、审计部、数据管理部四大关键职能，同时明确业务部门在特定战役中的协同职责，确保各项工作落地到岗、责任到人。

## （二）核心问题诊断

+   **两类问题并存**：当前本行信息科技风险管理的核心矛盾不在于"有没有"，而在于"好不好"与"确有缺失"。
    +   一方面，上述基础框架与安全设施已解决"有没有"的问题，但在执行深度和实质有效性上普遍存在**底线思维**：等保/密评重在通过而非整改落地；各类安全设备与平台的核心问题不在于基本处置流程，而在于**检测视野盲区**——超出默认配置与基础功能范围、需要主动设置或主动分析的能力普遍被忽略；各领域合规水平普遍接近监管最低要求。
    +   另一方面，存在少量缺口， 如**数据治理层面***，数据资产目录、数据分类分级等基础性工作尚未系统落地，成为评级提升的突出短板（对应战役八）。
+   **对评级的影响**：初步判断，当前各评级维度的总体状态是"维度均有覆盖，执行多在边缘"——底线思维虽可在各维度保持基本合格、避免明显失分，但在各维度上缺乏显著高于监管基准的质量优势，导致评级难以实现跨档提升。要从"基本合格"走向"优良"，必须在各维度上建立起超越底线的质量厚度。

## （二）2026年近期监管动向

+   以下政策动向高度确定，直接影响本计划2026年战役的工作重点：

    -   **《金融科技发展规划（2026—2030年）》**：现行2022-2025年规划到期，新一轮五年规划预计2026年发布，将明确"人工智能+"深度应用、数据资产价值释放等方向，直接驱动本计划后续阶段的战略重点。
    -   **AI算法风险专项监管**：2025年AI算法风险已成监管核心关注点，大模型备案管理要求、算法审计纳入信息科技审计范围等动作预计在2025-2026年陆续落地；金融领域AI模型风险管理专项指引有望出台。
    -   **数据安全双规落地**：金监总局数据安全办法（金规〔2024〕24号，2024年12月施行）和人民银行数据安全办法（2025年6月施行）相继落地，2026年是执法检查的关键之年，数据分类分级、敏感数据目录将是检查重点。
    -   **《商业银行信息科技风险管理指引》修订压力**：该文件历经15年未作整体修订，修订方向预期增加AI治理专章、数据资产化框架和第三方风险章节，2026年后存在修订可能。

## （三）2027—2028年中期趋势

+   以下趋势对本计划第二、三阶段工作安排有重要影响：

    -   **AI算法审计常态化**：AI算法审计有望成为信息科技审计的常规检查项，银行需建立算法模型全生命周期管理制度和可解释性保障机制。
    -   **密评覆盖率要求提升**：密评覆盖范围向重要业务系统扩展，核心系统密评覆盖率将成为现场检查重要指标。
    -   **数字金融能力评估**：监管对银行AI应用、数据资产、云原生架构等数字金融能力的评估要求提升，科技投入产出比将纳入综合评价视野。

## （四）2029—2030年长期趋势

+   以下长期趋势影响本计划第四、五阶段的工作方向：

    -   **实时监管与穿透监管全面建成**：EAST系统向实时、准实时数据采集演进，监管机构的非现场监测能力大幅提升，银行需具备监管数据自动采集、实时校验和接口对接能力。
    -   **AI伦理治理框架成熟**：AI伦理委员会将成为银行标配治理架构，算法公平性、可解释性、数据偏见防范成为常规合规要求。
    -   **数据资产化体系完善**：数据资产入表配套实施细则落地，金融数据流通交易规则明确，银行数据资产管理能力将面临全面评估。

# 第四章 方针原则与战略路径

## （一）核心原则

+   基于第二章的现状诊断与第三章的监管趋势分析，本方案确立以下核心原则：

-   **超越底线，质量优先**：拒绝以满足监管最低要求为隐性目标，以"实质有效"而非"形式达标"为交付标准；所有战役的任务动词优先采用"深化、提升、落地"，而非"建设、新增、发布"；已有基础上的质量提升，比重复建设更重要。
-   **提标聚焦，重点突破**：核心问题是质量标尺偏低而非基础缺失，不应将"提升质量标准"混同为"补建基础设施"；重点突破方向不能靠堆砌数量，须每年有意识地选定方向集中投入，形成显著优于监管基准的质量优势；全面提标保住基本分，重点突破才能推动评级跨档提升。
-   **对标监管，全量覆盖**：以《商业银行信息科技风险管理指引》八大评级维度为基准坐标系，建立"评级维度—战役—任务—交付物"的四级映射关系，确保每个评级维度都有对应的主责战役（D8信息科技审计因审计独立性要求，以独立保障机制覆盖而非设置独立战役），不留覆盖盲区。
-   **协同联动，打破壁垒**：以三大核心协作机制为抓手，推动信息科技部各专业板块与风险管理、审计部、数据管理部及业务部门高效联动，形成协同作战格局（详见第十一章）。
-   **务实落地，量化可考**：所有战役任务明确"牵头板块/部门+协同部门+交付物+量化验收标准+完成时限"，每项工作均有具体动作、可穿透验证的量化标准和证据要求。
-   **机制兜底，闭环管控**：以"整改销号"机制为保障，强化审计独立验证，形成"发现—认领—整改—验证—销号"全闭环（详见第十一章）。
-   **聚焦提升，证据先行**：优先启动需要长周期积累执行记录的维度（开发测试管理、运行管理），确保迎检时有充足、连续的过程证据链。
-   **跟踪监管，动态优化**：以年度复盘和监管政策跟踪为驱动，滚动调整各年度目标，确保计划始终对准监管前沿（参见第三章监管动态与趋势）。

## 战役一：治理架构与履职深化

**对应评级维度：D1 信息科技治理**

+   **战役定位**：IT治理的基础架构（CIO设置、三道防线、委员会机制、IT战略规划）均已具备；本战役的核心不是"有没有"，而是**履职记录的完整性与可查验性**——检查时能否拿出连续完整的会议纪要、CIO汇报记录、岗位分离执行台账，是决定评级的关键。

+   **牵头责任**：信息科技部·风险管理-制度处（部门层面）/ 风险管理部（全行层面）；协同：数据管理部、人力资源部

+   **五年演进路径**：

    | 年度 | 强度     | 年度战略重点                                                          |
    | ---- | -------- | --------------------------------------------------------------------- |
    | 2026 | 底线保障 | 履职证据链完整可查验：CIO汇报记录、委员会纪要连续≥4次、岗位分离无交叉 |
    | 2027 | 深化     | IT管理委员会运作规范化；三道防线履职质量提升                          |
    | 2028 | 成熟     | 信息科技管理体系3年综合评估；AI治理专章纳入治理框架                   |
    | 2029 | 适应     | 应对《商业银行信息科技风险管理指引》修订，调整治理结构                |
    | 2030 | 长效     | 科技风险治理成熟度综合评估；治理架构长效机制固化                      |

+   **核心工作机制**：CIO向行长直接汇报路径的制度保障；开发/测试/运维三类岗位的职责分离执行质量管控；IT管理委员会季度例会与决策留痕（≥4次/年）；IT战略规划与全行经营战略年度对齐核查；董事会科技风险专题汇报（≥4次/年）。

+   **具体工作内容**：

    -   **CIO履职记录制度化**：从"有汇报"向"汇报有记录、记录可举证"推进——统一汇报模板（含议题清单、会议结论、跟踪事项），确保每次汇报留有可迎检的完整记录台账。
    -   **IT管理委员会运作规范化**：从"会议有开"向"决策有追踪、落实有验证"推进——标准化议题设置和纪要格式，每次例会冒头核查上次决策落实情况，台账连续可查。
    -   **岗位职责分离落地**：从"制度有规定"向"系统中权限无交叉"推进——逐人核查开发/测试/运维三类岗位实际权限配置，消除交叉点，维护执行台账供迎检抽查。
    -   **IT战略规划年度对齐**：从"战略规划已发布"向"执行偏差有追踪"推进——设置每年Q4的战略对齐审查节点，对执行偏差逐项记录并向IT管理委员会汇报调整计划。
    -   **科技风险纳入全面风险管理框架**：从"框架性表述"向"报告路径清晰可操作"推进——与风险管理部明确科技风险在全行风险报告体系中的层级定位、上报频次和格式标准。

+   **典型交付物**：《CIO岗位职责说明书》（含履职记录）、《信息科技战略规划》（年度执行跟踪）、《岗位职责分离矩阵》、IT管理委员会季度会议纪要、《科技风险治理手册》

## 战役二：IT风险管理体系深化

**对应评级维度：D2 信息科技风险管理**

+   **战役定位**：构建量化、可视、闭环的信息科技风险管理体系，从"有制度有框架"升级到"数据真实、指标有效、预警及时"；以2026年为起点持续积累高质量数据，支撑2030年科技风险量化预测模型的最终重点突破成果。

+   **牵头责任**：信息科技部·风险管理-制度处（部门层面）/ 风险管理部（全行层面）；协同：数据管理部、各业务部门

+   **五年演进路径**：

    | 年度 | 强度          | 年度战略重点                                                              |
    | ---- | ------------- | ------------------------------------------------------------------------- |
    | 2026 | 攻坚·重点突破 | KRI体系完善（指标质量提升+自动采集≥60%）；全行风险评估；ITMIS/SOC能力激活 |
    | 2027 | 深化          | KRI自动采集≥80%；风险量化方法论引入；外包风险量化                         |
    | 2028 | 重点突破      | 内部模拟检查机制建立并运作（整改完成率≥95%）；科技风险全景地图            |
    | 2029 | 深化·重点突破 | 监管数据自动化实时采集接口上线；量化预测模型建设启动                      |
    | 2030 | 重点突破      | 科技风险量化预测模型成熟验证（4年数据积累成果）                           |

+   **核心工作机制**：KRI指标体系的双维度持续优化（指标质量：领先指标优先；采集质量：自动采集率持续提升）；分层分级风险报告的频率和质量管控（周/月/季三级）；年度全行信息系统风险评估（RCSA方法论）；ITMIS/SOC平台的实际应用深化（激活已有但未充分使用的模块）；风险事件管理与损失数据持续积累；持续优化KRI内部数据采集与分析质量，为监管评级系统（GIRR）提供高质量输入。

+   **具体工作内容**：

    -   **KRI指标体系优化**：从"人工报送为主"向"自动采集为主、有效预警"推进——逐指标审查采集路径，识别可改造数据源，按季度推进自动化；同步开展年度指标有效性评审，淘汰不能真实反映风险水位的指标。
    -   **年度全行风险评估（RCSA）**：从"制度有规定"向"全系统覆盖、结果驱动整改"推进——细化RCSA方法论（分类标准、评估维度、打分规则），按系统重要性分批执行，评估结果与整改追踪台账挂钩，年度复评时核查落实情况。
    -   **分层分级风险报告体系**：从"有报告"向"内容实质化"推进——分别细化运营层/管理层/决策层报告模板，明确每份报告的强制内容项（区分数字罗列与真实风险判断），逐批次核查报告质量是否从数据堆砌转向分析判断。
    -   **风险事件管理与损失数据积累**：从"事件有记录"向"分类标准化、根因可追溯、损失可量化"推进——统一事件分类（对齐监管分类），强化"记录→损失统计→根因分析→经验固化"全流程执行，为后期量化建模积累基础数据。
    -   **工具平台深化应用**：从"平台已部署"向"功能实际使用率提升"推进——逐模块梳理"已配置但未使用"的功能，按风险优先级制定激活计划，每季度验收激活进展，年度评估实际应用深度。

+   **典型交付物**：《信息科技风险管理框架》（年度修订）、《KRI指标体系》（含自动采集覆盖率统计）、《年度风险评估报告》（含风险热力图）、各层级风险报告、《风险事件损失分析报告》（季度）

## 战役三：信息安全深化攻坚

**对应评级维度：D3 信息安全**

+   **战役定位**：在ISMS/ISO 27001认证、等保测评、密评已通过的基础上，重点提升安全体系的执行实质性——激活现有安全产品的完整功能（消除"已购未用"），深化访问控制、漏洞管理、安全监测与响应的质量，以穿透检查通过（而非证书维护）为验收标准。

+   **牵头责任**：信息科技部·网络安全；协同：信息科技部·风险管理-制度处、风险管理部、数据管理部

+   **五年演进路径**：

    | 年度 | 强度          | 年度战略重点                                                            |
    | ---- | ------------- | ----------------------------------------------------------------------- |
    | 2026 | 攻坚·重点突破 | 安全产品功能系统性激活；PAM精细化；安全基线自动化；零信任启动；红蓝对抗 |
    | 2027 | 深化          | 零信任覆盖核心系统；漏洞修复周期≤15天；全员安全培训全覆盖               |
    | 2028 | 深化          | AI模型安全管控框架完善；攻防演练常态化≥2次/年；安全能力覆盖扩展         |
    | 2029 | 智能化        | SOC关联规则大幅扩展；UEBA引入；威胁响应时效较基准-50%                   |
    | 2030 | 领先          | AI伦理审查机制；安全事件重复率≤5%；安全能力行业领先                     |

+   **核心工作机制**：安全产品功能激活路线图的制定与执行（逐产品梳理已购能力与实际启用差距，消除底线思维导致的功能闲置）；特权访问管理（PAM）全链路管控（申请—审批—记录—审计）；安全基线自动化检测与整改闭环；零信任架构分阶段落地；红蓝对抗演练（无预告）；数据安全双规合规整改。

+   **具体工作内容**：

    -   **安全产品功能激活**：从"产品已采购"向"功能实际有效启用"推进——逐产品整理"已购功能 vs 实际启用"对比表，按风险覆盖价值排序，分批激活并验收每项功能的实际效果，而非仅记录"已开启"。
    -   **PAM特权账号管理深化**：从"有PAM系统"向"特权操作全量受控可审计"推进——梳理全量特权账号（含共享账号、服务账号），清理闲置账号，将所有特权操作纳入日志或录像审计，按季度全量审查并清零无效账号。
    -   **漏洞管理深化**：从"扫描有执行"向"修复有时限、有验证、有留痕"推进——扩展扫描覆盖面，完善按严重程度分级的整改期限管控，每次修复后留存可验证凭据，定期开展修复有效性复核。

    -   **数据资产目录建立与维护**：制定数据资产盘点方法论（维度：系统×数据集×数据类型×敏感程度×数据负责人）；推动各业务部门确认本部门的数据资产清单；建立新系统上线时数据资产登记的强制流程；定期（建议半年）开展目录准确性核查和更新。
    -   **数据分类分级精细化**：对照金规〔2024〕24号的分类分级要求，梳理现有分类框架与监管要求的差距；完成精细化重新标注（明确每类数据集的类别、级别和对应管控措施）；核查关键系统的实际数据处理行为是否与分类分级结论一致；建立年度复审机制（业务变化时触发重新评估）。
    -   **数据质量月度检核**：建立数据质量检核规则集（覆盖：完整性、准确性、一致性、及时性四个维度）；配置检核工具并对接关键数据源；每月执行检核并出具报告；对质量问题建立整改追踪；逐月对比质量趋势。
    -   **个人信息保护合规审计**：梳理全行个人信息采集、存储、处理和共享场景清单；对照《个人信息保护法》逐项评估合规差距；制定整改计划并推动执行；开展年度专项审计（可委托内审部门或外部机构）；将审计发现纳入整改销号平台跟踪。
    -   **数据血缘追踪建设**：明确血缘追踪的目标范围（优先覆盖核心数据集）；选型或利用现有数据管理平台功能；梳理核心数据从源头到应用的完整流转路径；建立数据变更时血缘关系自动更新的机制。

+   **典型交付物**：《全行数据资产目录》（年度维护）、《数据分类分级方案》、《数据质量检核报告》（月度）、《数据治理专项审计报告》

    -   **钓鱼演练机制落地**：从"未系统开展"向"每年至少2次、点击率可见改善"推进——设计多种伪装场景（外部攻击、内部社工等），执行时无预告，统计点击率（分部门/分岗位），对点击人员强制针对培训，逐次对比改善趋势。

+   **适用场景**：重大系统上线、新业务投产、监管新规落地、新技术（AI/云）应用、核心数据变更、年度风险评估等所有关键场景。

+   **运作模式（三方会签制）**：
    -   事前——数据管理部定义数据标准，信息科技部制定技术与安全设计，风险管理部审核合规性，三方会签方可立项
    -   事中——信息科技部·系统运行保稳定，网络安全负责威胁监测，风险管理部实时监测KRI预警
    -   事后——审计部独立后评价，结论反馈至下一轮三方会签改进

+   **常设工作节奏**：双周例会（三方碰头，通报进展、消解摩擦）；月度联合风险报告（三方共同输出，上报科委会备案）。

## （三）科委会（高层治理背书）

+   **定位**：依托全行现有科技委员会（科委会）作为高层治理背书机制，无需新设机构；职能限定于：批准年度资源方案、裁决跨部门重大争议、审议应急调整；日常执行由三角联席工作制承载，科委会不介入日常运营。

+   **运作**：在科委会现有议事机制下，将本计划重大事项纳入科委会议程；常设办公室设在信息科技部·风险管理-制度处，负责日常督办与议题准备；紧急事项24小时内提请科委会审议。

## （四）"问题整改销号"闭环机制（监督与问责层）

+   **管理工具**：统一的"监管评级提升任务管理平台"（数字化看板），实现任务认领、进度跟踪、验证销号全线上化。

+   **强制流程**：发起（信息科技部·风险管理-制度处生成《问题整改清单》）→ 认领（3个工作日内，制定整改措施和SLA）→ 验证（审计部非现场+现场穿透测试）→ 销号（仅审计部出具"验证通过"意见后方可销号）。

+   **红线原则**：未通过审计验证严禁销号；逾期未完成自动升级至科委会督办，与绩效考核挂钩。

## （五）IT审计独立性保障机制（对应D8评级维度）

+   审计部不参与科委会决策表决；不参与三角联席的事前会签和事中监控；不参与整改标准制定；有权对任何战役整改成效提出独立质疑。

+   **审计工作体系**：每年Q1制定年度审计计划；三年滚动IT审计计划；全年≥3次专项审计（Q2/Q3过程审计，Q4"整改回头看"）；高风险领域聘请外部审计机构独立复核。

# 第十二章 保障机制

## （一）组织保障

+   以"风险—科技—数据"三角联席工作制（详见第十一章）为主要执行抓手，常设办公室（信息科技部·风险管理-制度处）负责日常督办、每周汇总各专业板块进展；各战役"专项工作组"明确牵头人，确保执行到位。科委会作为高层资源保障与争议裁决机制，按季度频率运转。各业务部门指定固定联络人参与BIA、数据Owner确认等协同工作。

## （二）资源保障

+   专项整改预算优先保障，重点用于安全能力提升工具、CMDB/ITMIS平台升级、SAST/DAST工具采购、第三方审计/测试等；人力资源部优先落实关键岗位招聘和双向挂职计划；跨部门人力借调由科委会统一审批。

+   五年预算规划原则：

-   刚性优先保障：灾备建设、安全运营、监管合规相关投入不得以预算压缩为由延期
-   年度滚动预算：依据当年评估结论动态调整投入重点
-   四类投入：工具平台采购与建设、系统改造升级、外部咨询与审计、人员培训与能力建设

## （三）考核与激励

-   **双向打分制**：信息科技部（含各专业板块）绩效，30%由风险管理部打分；风险管理部绩效，20%由信息科技部打分；审计部绩效由审计委员会独立评价，不纳入双向打分
-   **红线问责**：因部门推诿导致评级下降或发生重大风险事件的，部门负责人年度绩效一票否决；审计验证发现"虚假整改"的，直接移交纪检监察部门处理
-   **激励机制**：对战役攻坚成效显著、按时完成任务的板块和个人，给予绩效加分和评优表彰

## （四）沟通联动保障

+   主动对接监管机构，及时了解最新监管评级要求，主动汇报工作进展；发生重大科技事件须按监管要求时限完成事件报告；加强政策性银行同业交流，借鉴先进经验为后续年度计划提供参考。

## （五）应急调整机制

### 计划降级预案

    | 触发场景                          | 应急响应                                                     | 资源调整                       |
    | --------------------------------- | ------------------------------------------------------------ | ------------------------------ |
    | 重大信息安全事件（数据泄露/勒索） | 24小时内召开紧急会议，暂停非核心战役，资源集中处置与根因整改 | 战役九、十降级为维持性任务     |
    | 监管专项检查/突击检查             | 48小时内成立专项应对小组，对检查涉及维度优先完善证据链       | 根据检查范围动态调整战役优先级 |
    | 关键供应商重大事故                | 启动外包退出应急预案，评估对灾备和运行的影响                 | 战役七升级为最高优先级         |
    | 监管评级标准重大调整              | 一周内完成新标准与十大战役映射分析，调整覆盖方案             | 视影响范围新增或调整战役内容   |

### 优先级保底原则

+   无论发生何种冲击，以下"保底四战役"的执行不得中断：

-   战役三（信息安全）——一级关注领域，直接决定评级底线
-   战役四（开发测试）——证据链不可中断，一旦断裂无法补救
-   战役五（运行管理）——证据链不可中断，一旦断裂无法补救
-   战役六（业务连续性）——一级关注领域，直接决定评级底线

# 第十三章 附则

+   本计划自发布之日起实施，由科委会负责解释。各部门及专业板块需根据本计划制定具体实施细则，确保任务落地到岗、责任到人。
+   本计划每年12月由科委会组织年度复盘，结合监管政策变化和战役推进情况，适时调整优化五年路线图和年度重点工作。

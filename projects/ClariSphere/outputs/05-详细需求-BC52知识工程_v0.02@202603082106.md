# 3 Capability子域划分

## 3.1 知识生产链路分析

+   BC-52的核心业务是一条**知识生产链路**：从外规原文进来，经过解析、结构化、映射、封装，最终以合规包的形式输出给下游。这条链路上的7个自然节点，就是7个子域的由来。

+   知识生产链路如下图所示

    ```graph
    ┌─────────────────────────────────────────────────────────────────────────────────────┐
    │                         BC-52 知识生产链路                                          │
    ├─────────────────────────────────────────────────────────────────────────────────────┤
    │                                                                                     │
    │   外规条文（BC-51采集）                                                              │
    │       │                                                                             │
    │       ▼                                                                             │
    │   ┌──────────┐     ┌──────────┐                                                    │
    │   │ SD-05    │────▶│ SD-04    │                                                    │
    │   │ 外规解析 │     │ 要求管理 │──────────────┐                                     │
    │   │ 管理     │     │          │              │                                     │
    │   └──────────┘     └──────────┘              │                                     │
    │                                              ▼                                     │
    │   ┌──────────┐                        ┌──────────┐     ┌──────────┐                │
    │   │ SD-01    │───────────────────────▶│ SD-06    │────▶│ SD-07    │───▶ 合规包     │
    │   │ 场景管理 │                        │ 映射管理 │     │ 合规包   │    （给BC-11） │
    │   └──────────┘                        └──────────┘     │ 管理     │                │

    │   │ SD-02    │────▶│ SD-03    │──────────────┘                                     │
    │   │ 控制管理 │     │ 责任管理 │                                                    │
    │   └──────────┘     └──────────┘                                                    │
    │                                                                                     │
    │   输入侧(What)         架构侧(管什么+怎么管)      连接层        输出侧(打包交付)   │
    └─────────────────────────────────────────────────────────────────────────────────────┘
    ```

    +   图 知识生产链路

+   7个SD的定位：
    -   **输入侧**（What——必须做到什么）：SD-05接收外规，SD-04拆解为结构化要求
    -   **架构侧**（管什么+怎么管）：SD-01定义场景（管什么资源/活动），SD-02定义控制点和方案（怎么管），SD-03生成责任点（谁来管）
    -   **连接层**（What↔How）：SD-06把要求和控制点、场景点映射起来，用方法论框架审视覆盖度
    -   **输出侧**（打包交付）：SD-07把映射好的内容封装为合规包，交给下游

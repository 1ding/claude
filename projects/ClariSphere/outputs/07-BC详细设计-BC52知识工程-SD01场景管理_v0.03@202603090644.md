# 1 总则

+   文档编号：BC52-SD01
+   文档名称：知识工程 场景管理详细设计
+   目的：定义 BC-52 知识工程 SD01 场景管理子领域的详细设计方案，覆盖领域模型、应用层、接口、数据模型、前端交互、权限和测试设计

## 3.5 FL-SM-04 浏览与检索场景树

+   **功能目标**：按T/M/G空间加载场景树，支持展开/收起和关键字搜索
+   **使用角色**：UP02控制架构师
+   **接口对应**：P-SM-01、P-SM-06（第6章）

+   技术实现要点：
    -   场景树缓存：按空间维度缓存完整场景树（Key: engineer:scenario-tree:{space}，TTL 10分钟）
    -   查询路由：优先查Redis缓存，未命中时查DB并回填
    -   关键字搜索：基于数据库LIKE查询（P1阶段场景点数据量2000+，无需引入ES）

+   异常处理如下表所示

    | 异常场景     | 处理策略             |
    | ------------ | -------------------- |
    | 缓存不可用   | 降级为直接查询数据库 |
    | 空间参数无效 | 返回E-4000007        |

    +   表 浏览与检索异常处理

## 4.4 CompositeScenario 聚合

+   **设计说明**：组合场景将多个基础场景点按"资源1 [+ 资源1的状态] + 资源2"公式组合为一个预定义的复合场景。三个字段（primaryPointId、statePointId、secondaryPointId）均为 ScenarioPoint 的 ID 引用，区别仅在于语义角色：
    -   primaryPointId（资源1）：被管控的核心资源，如"数据"、"数据库"
    -   statePointId（资源1的状态，可选）：资源所处的状态或阶段，如"数据传输"、"数据存储"；该场景点在 T/M/G 场景树中通常作为资源节点的子节点存在（如 数据 > 数据传输）
    -   secondaryPointId（资源2）：组合中的第二个场景维度，如"笔记本"、"内网"、"变更管理"
+   statePointId 不是独立的状态枚举，而是复用场景点体系——"传输"、"存储"等状态/阶段描述词在 SM-R-02 约束下是合法的场景点名称

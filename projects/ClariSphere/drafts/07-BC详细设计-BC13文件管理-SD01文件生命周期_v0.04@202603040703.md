## 3.2 文件上传流程（FL-FM-01）

### 3.2.1 流程概述

文件上传流程负责将业务BC提交的文件安全写入OBS并完成元数据持久化。流程目标：保证幂等性、完成类型/大小校验、将文件写入OBS，并以SCANNING状态入库等待SD03异步扫描。触发条件：业务BC调用 POST /v1/files，携带文件流和 `X-Client-File-Id`。结束条件：File 聚合以 SCANNING 状态持久化成功，FileUploadedEvent 已入队。

## 3.3 文件软删除流程（FL-FM-02）

### 3.3.1 流程概述

文件软删除流程将文件标记为 DELETED 状态，OBS 对象保留至后台异步清理任务执行。流程目标：安全删除文件（状态校验），防止误删 SCANNING/QUARANTINED 状态的文件。触发条件：业务BC调用 DELETE /v1/files/{id}。结束条件：File 状态持久化为 DELETED，元数据缓存已主动失效。

+   **FileApplicationService** 方法清单如下表所示。

    +   表 FileApplicationService 方法清单

+   **应用层结构说明：** 本文档将全部 7 个用例方法集中在 `FileApplicationService` 单类中（未拆分为 `UploadFileUseCase` 等独立类）。P1 阶段各用例共享相同依赖（FileRepository、ObjectStoragePort、IamAcl），集中编排有利于统一事务管理；P2+ 如用例数超过 10 个，可按用例群拆分独立类。

+   **uploadFile 协调步骤：**
    1.   查询 Redis 中 `clientFileId`，若存在则返回 E-4091301 及已有 fileId（幂等拦截）
    2.   写入幂等键到 Redis（`SET clientFileId:{id} fileId TTL=24h`）
    3.   执行文件大小校验（≤100MB）和类型白名单校验（MIME + Magic Number 双检）
    4.   调用 `ObjectStoragePort.putObject()` 写入 OBS，获取 FileStorageResult
    5.   判断是否覆盖上传（clientFileId 是否已有关联 File）：新文件调用 `File.create()`，覆盖上传调用 `File.createVersion()`
    6.   在同一数据库事务内持久化 File + FileVersion
    7.   事务提交后从 File 聚合收集 FileUploadedEvent，发布到 RocketMQ（消息发送失败不回滚事务）

+   **downloadFile 协调步骤：**
    1.   加载 File 聚合（Redis 缓存优先，未命中查 MySQL）
    2.   校验文件状态不为 SCANNING / QUARANTINED / DELETED（FM-R-03）
    3.   presigned 模式：调用 `ObjectStoragePort.getPresignedUrl(storageKey, expireType)` 返回签名URL
    4.   stream 模式：调用 `ObjectStoragePort.getObject(storageKey)` 返回文件流

+   **getSignedUrl 协调步骤：**
    1.   加载 File 聚合（Redis 缓存优先）
    2.   校验文件状态不为 SCANNING / QUARANTINED / DELETED（FM-R-03；违反返回 E-4221301）
    3.   调用 `ObjectStoragePort.getPresignedUrl(storageKey, expireType)` 返回签名URL和过期时间

## B.1 缓存明细

+   下表说明 SD01 涉及的 Redis 缓存项设计。

    | 缓存项名称 | Key 模板                         | 数据来源     | TTL               | 失效策略                                    | 一致性保证方式 |
    | ---------- | -------------------------------- | ------------ | ----------------- | ------------------------------------------- | -------------- |
    | 文件元数据 | `file:meta:{fileId}`             | t_file       | 30min             | 写时删除（softDelete/状态变更时主动删 Key） | Cache-Aside    |
    | 签名URL    | `file:url:{fileId}:{expireType}` | OBS 签名接口 | 与 URL 有效期一致 | Write-Through；检查 TTL，过期重新签发       | Write-Through  |

## B.2 性能优化措施

+   下表说明 SD01 的性能目标和优化方案。

    | 优化场景       | 性能目标       | 优化方案                         | 实现要点                                                   |
    | -------------- | -------------- | -------------------------------- | ---------------------------------------------------------- |
    | 文件元数据查询 | P99 < 100ms    | Redis Cache-Aside                | 命中率目标 >80%；写入/删除时同步主动失效缓存 Key           |
    | 文件上传吞吐   | 小文件P99 < 3s | 病毒扫描异步化（SD03负责）       | 上传响应不等待扫描；业务BC须处理 SCANNING 中间态           |
    | 签名URL签发    | P99 < 500ms    | 缓存命中复用，有效期内不重复签发 | 检查 Redis TTL；TTL>0时直接返回缓存URL，避免重复调 OBS SDK |

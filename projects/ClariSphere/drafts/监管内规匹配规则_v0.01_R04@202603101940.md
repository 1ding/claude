# 1 概述

+   文档编号：GUIDE-REG-002
+   文档名称：监管条文与内规条文匹配关系规则
+   文档密级：内部资料

## 1.1 目的

+   本文档定义监管条文义务记录与内部规章制度义务记录之间的匹配判定规则，用于评估内规对监管要求的覆盖情况，识别合规空白。
+   本文档与《监管条文结构化拆解指南》（GUIDE-REG-001）配套使用，两者共享同一套义务记录 schema。

## 1.2 前提条件

+   参与匹配的两侧记录均已按 GUIDE-REG-001 完成结构化拆解，字段体系一致。
+   内规记录在 GUIDE-REG-001 基础上额外包含以下字段：

| 附加字段  | 说明                                     |
| --------- | ---------------------------------------- |
| `scope`   | 内规适用范围，如适用部门、系统或业务场景 |
| `doc_ref` | 内规来源文件编号，如 `DSP-OPS-012`       |

# 2 匹配判定规则

## 2.1 主键匹配（必要条件）

+   主键匹配为匹配的必要条件，两个字段须同时满足，才进入后续评分流程：

| 主键字段      | 匹配规则                                         |
| ------------- | ------------------------------------------------ |
| `object.code` | 内规客体 code 与监管客体 code 完全一致（同粒度） |
| `action`      | 两者归一化动词一致（均来自 GUIDE-REG-001 第 4.3 节行为词表） |

+   客体粒度不同时的处理规则：

-   内规客体为监管客体的**父类**（如监管 `M4.2`，内规 `M4`）→ 主键不命中，判定为**合规空白**。父类制度不能证明子类义务被覆盖；需内规明确到同一粒度才算覆盖。
-   内规客体为监管客体的**子类**（如监管 `M4`，内规 `M4.2`）→ 主键命中，但视为**部分覆盖**，覆盖率按子类占父类的比例估算，需人工确认是否充分。

+   主键均不命中时，直接判定为**合规空白**，不进入评分流程。

## 2.2 覆盖维度评分

+   主键命中后，对以下五个维度逐一判断：

| 维度           | 字段            | 判断规则                                                                 | 不满足时结论     |
| -------------- | --------------- | ------------------------------------------------------------------------ | ---------------- |
| 主体覆盖       | `subject`       | 内规主体范围 ⊇ 监管主体范围，见 2.3 节                                   | 主体覆盖不足     |
| 模态充分       | `modality`      | 内规模态强度 ≥ 监管模态强度，见 2.4 节                                   | 模态不足         |
| 规则覆盖率     | `rules`         | 监管每条规则内容，内规中有对应条目可覆盖；覆盖率 = 覆盖条数 / 总条数    | 部分覆盖或空白   |
| 时限充分       | `deadline`      | 内规时限 ≤ 监管时限（更严或相同），见 2.5 节                             | 时限不足         |
| 目标一致性     | `targets`       | 内规与监管的 COAST 目标有交集（非强制，作为参考维度）                    | 目标偏差（参考） |

## 2.3 主体覆盖规则

+   监管主体分为两类，由监管记录中 `subject.type_class` 字段标记：

| 类型 | 归一化主体                                                                               | 覆盖判断方式                                               |
| ---- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 通用 | 数据处理者、重要数据处理者、任何组织或个人、境内组织或个人、数据安全负责人、直接负责的主管人员、直接责任人员 | 按级别匹配，名称不限，见下方级别规则               |
| 专属 | 关键信息基础设施运营者、数据交易中介机构、国家机关、行业主管部门、统筹协调机构、受托方   | 排他适用；除非项目配置声明本企业属于该类，否则不适用       |

+   **通用主体的级别匹配规则**：监管主体的 `category` 字段决定所需的内规主体级别，名称不作限制：

| 监管 `category` | 对应级别 | 内规主体示例                   | 匹配规则                     |
| --------------- | -------- | ------------------------------ | ---------------------------- |
| 组织 / 角色     | 组织级   | 本公司、公司、天帷科技         | 内规主体为公司整体即覆盖充分 |
| 岗位            | 岗位级   | 数据安全负责人、首席信息安全官 | 内规主体为对应岗位即覆盖充分 |

+   部门级内规主体（如"信息科技部"）对组织级监管义务视为**部分覆盖**（仅覆盖该部门范围，全公司范围未闭合）。
+   **专属主体**：项目初始化时声明本企业属于某专属类型后，该类型义务视为适用，按通用规则继续判断覆盖。
+   示例：

| 监管主体               | type_class | category | 内规原文   | 覆盖结论                   |
| ---------------------- | ---------- | -------- | ---------- | -------------------------- |
| 数据处理者             | 通用       | 组织     | 本公司     | 覆盖充分                   |
| 重要数据处理者         | 通用       | 组织     | 本公司     | 覆盖充分                   |
| 数据处理者             | 通用       | 组织     | 信息科技部 | 部分覆盖（仅该部门范围）   |
| 数据安全负责人         | 通用       | 岗位     | 数据安全官 | 覆盖充分（岗位级对岗位级） |
| 数据安全负责人         | 通用       | 岗位     | 本公司     | 不适用（级别不匹配）       |
| 关键信息基础设施运营者 | 专属       | 组织     | 本公司     | 不适用（除非项目配置声明） |

## 2.4 模态强度排序

+   强度从高到低：`应` > `宜` > `可以`。
+   判断规则：内规模态强度 ≥ 监管模态强度，则模态充分。反之为模态不足。
+   示例：监管为"应"，内规为"宜" → 模态不足；监管为"宜"，内规为"应" → 模态充分。

## 2.5 时限强度排序

+   强度从严到宽：`立即` > `及时` > `N 日内（N 越小越严）` > `定期` > `无`。
+   判断规则：内规时限强度 ≥ 监管时限强度（即内规要求更快或相同），则时限充分。
+   监管时限为 `null` 时，时限维度视为充分，不参与评分。

# 3 底层匹配对

## 3.1 单对匹配结论

+   每条监管义务记录与每条内规义务记录形成一个匹配对，按 2.2 节五个维度判断结论：

| 结论     | 判定条件                                                         |
| -------- | ---------------------------------------------------------------- |
| 全覆盖   | 主键命中 + 主体充分 + 模态充分 + 规则覆盖率 100% + 时限充分     |
| 部分覆盖 | 主键命中 + 规则覆盖率 > 0 且 < 100%，或时限不足，或主体不足     |
| 模态不足 | 主键命中 + 规则覆盖率 100% + 模态强度低于监管                   |
| 合规空白 | 主键未命中，或规则覆盖率 = 0                                     |
| 超额覆盖 | 全覆盖且内规在模态或时限上比监管更严（记录备查，不视为问题）     |

+   优先级：合规空白 > 模态不足 > 部分覆盖 > 超额覆盖 > 全覆盖。

## 3.2 单对匹配记录格式

+   每个匹配对输出一条记录：

```json
{
  "regulation_id":      "数据安全法§29-B",
  "internal_policy_id": "DSP-OPS-012",
  "pair_result":        "partial_coverage",
  "dimensions": {
    "subject_scope":  true,
    "modality_level": true,
    "rule_coverage":  0.67,
    "deadline_match": false
  },
  "covered_rules":   ["①立即采取处置措施", "②及时告知用户"],
  "uncovered_rules": ["③向主管部门报告"]
}
```

# 4 两种分析视角

+   基于底层匹配对，从两个方向聚合，回答不同问题：

| 视角     | 主键   | 问题                       | 关注点                           |
| -------- | ------ | -------------------------- | -------------------------------- |
| 法规视角 | 监管条款 | 这条监管义务是否被充分满足？ | 多条内规联合覆盖后的总体覆盖度   |
| 内规视角 | 内规条款 | 这条内规制度有没有法规依据？ | 有无法规支撑，不评价法规是否满足 |

## 4.1 法规视角：覆盖度分析

+   以监管条款为主键，聚合所有与之匹配的内规记录，计算总体覆盖度。
+   **聚合规则**：

-   规则覆盖：取所有匹配内规 `covered_rules` 的**并集**，计算对监管 `rules` 的总覆盖率
-   模态充分：取所有匹配内规中**最严**的模态，与监管模态比较
-   时限充分：取所有匹配内规中**最严**的时限，与监管时限比较
-   主体充分：至少一条内规的主体级别满足要求即充分

+   **覆盖度结论**枚举值与单对结论一致（见 3.1 节），基于聚合后数值重新判定。
+   **法规视角汇总格式**：

```json
{
  "regulation_id": "数据安全法§29-B",
  "matched_policies": [
    { "internal_policy_id": "DSP-OPS-012", "covered_rules": ["①", "②"] },
    { "internal_policy_id": "DSP-OPS-015", "covered_rules": ["③"]       }
  ],
  "coverage_summary": {
    "result":           "全覆盖",
    "rule_coverage":    1.0,
    "modality_adequate": true,
    "deadline_adequate": true,
    "uncovered_rules":  []
  }
}
```

+   无内规命中时：`matched_policies` 为空数组，`coverage_summary.result` 填 `"合规空白"`。

## 4.2 内规视角：依据充分性分析

+   以内规条款为主键，列出所有与之主键命中的监管条款，评价该内规的法规依据是否充分。
+   **不评价法规是否被充分满足**——同一条法规可能还由其他内规覆盖，此处仅关注本条内规的依据来源。
+   **依据类型**：

| 依据类型 | 判定条件                                   |
| -------- | ------------------------------------------ |
| 直接依据 | 主键完全命中（object code 相同，action 相同） |
| 间接依据 | 主键部分命中（客体为子类，见 2.1 节）      |

+   **依据充分性结论**：

| 结论       | 判定条件                         |
| ---------- | -------------------------------- |
| 依据充分   | 有 1 条以上直接依据              |
| 依据部分   | 无直接依据，但有间接依据         |
| 无明确依据 | 无任何监管条款与该内规主键命中   |

+   **内规视角汇总格式**：

```json
{
  "internal_policy_id": "DSP-OPS-012",
  "matched_regulations": [
    { "regulation_id": "数据安全法§29-B", "basis_type": "直接依据" },
    { "regulation_id": "网络安全法§25",   "basis_type": "间接依据" }
  ],
  "basis_assessment": {
    "result":               "依据充分",
    "direct_basis_count":   1,
    "indirect_basis_count": 1
  }
}
```

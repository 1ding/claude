### 2.2.4 问题空间全景

+   透管云以「合规知识生产」（供给侧）和「企业合规治理闭环」（消费侧A）、「个人知识消费」（消费侧B）构成三大业务价值生态
+   供给侧的核心业务问题是：如何将海量分散的外部监管法规，经由标准化的解析-映射-封装流程，转化为可被企业直接落地的结构化合规知识产品
+   消费侧A的核心业务问题是：如何建立从合规要求到管理制度、技术方案、执行行动的全链路穿透可见性，使企业真正做到要求↔落实不脱节
+   消费侧B提供低门槛的个人合规知识获取渠道，并作为企业客户的引流漏斗
+   三大生态通过8库6图1包的数据架构和6链穿透验证模型（L1治理穿透/L2合规落地/L3制度溯源/L4技术落地/L5责任落实/L6风险防控）在技术层面打通
+   四大困境（DLM001新规比对地狱、DLM002监管检查拷问、DLM003管理汇报哑口、DLM004员工执行茫然）是问题空间的顶层框架，指引核心域边界划定和优先级决策

    | 团队边界     | BC边界尽量与组织团队边界对齐                   | 不以此为主要判据           | 低     |

# 6 领域事件全景

+   本章识别和定义35个领域事件，包括跨域事件（触发其他BC响应）和域内事件（驱动本BC聚合状态流转），建立事件流转全景图

## 6.1 事件识别方法

+   **来源**：EventStorming工作坊产出（KA-01计划）+ 实体生命周期状态转换（阶段2成果SI-03）+ 跨BC异步集成场景（第5章CM关系）
+   **命名规范**：英文PascalCase + 过去时态（`{Entity}{Action}ed`）；中文"{实体}已{动作}"
+   **事件分类**：跨域事件（触发其他BC响应）、域内事件（BC内部消费）
+   **版本策略**：事件载荷采用向后兼容设计，新增字段可选，删除字段需版本升级

## 6.2 事件分类

+   **跨域事件**：由一个BC发布，被其他BC订阅并响应；是异步集成的核心机制
+   **域内事件**：在同一BC内部触发聚合状态流转或工作流推进；不对外发布

## 7.2 聚合识别方法

+   **主要判据**：事务一致性边界——同一事务中必须保持一致的实体，划入同一聚合
+   **辅助判据**：实体生命周期独立性——生命周期独立的实体可考虑独立聚合
+   **设计原则**：聚合应尽量小（Small Aggregates），跨聚合引用只允许通过聚合根ID

# 附录A（规范性）统一语言

+   本附录定义 ClariSphere 透管云领域设计统一语言，适用于本文档及所有下游阶段文档
+   所有文档中出现的术语必须与本附录保持一致

## A.1 统一语言原则

+   **唯一性**：全文同一术语名称含义唯一，禁止同义词混用
+   **边界性**：同一术语在不同BC中含义不同时，必须拆分为不同术语（如"用户"在BC-10和BC-20的含义不同，须明确区分"登录账号"和"知识消费用户"）
+   **显示性**：新术语首次出现必须在本附录注册，并提供定义；下游文档不可自行引入未在本附录注册的领域术语
+   **治理性**：术语变更须通知所有关联BC的负责团队，并更新下游文档

---

**§3.X FL-PM-03 待入库编辑**

**§3.X.1 流程概述**

+   **流程目标**：制度管理员对处于"待入库"状态的制度进行元数据与解析结果修订，修正导入过程中的录入错误或解析错误，不涉及制度实质内容变更。
+   **触发条件**：UR-10 制度管理员在制度清单中选中一条"待入库"制度，发起编辑操作；或 FL-PM-07 退回待入库后系统自动跳转至本流程。
+   **适用状态**：仅限"待入库"制度。
+   **操作角色**：UR-10 制度管理员（不含 UR-03 制度编写者）。
+   **编辑范围**：
    -   元数据字段：制度名称、分类、版本号等录入字段
    -   解析结果：章节层级、章节标题的人工修正
    -   不包括：制度实质内容修订（制度正文、业务条款，属运营生命周期 P2+）
+   **结束条件**：管理员保存修订，制度仍处于"待入库"状态；或直接发起"提交入库"（调用 FL-PM-01.3），制度进入"已入库"状态。

**§3.X.2 与 FL-PM-07 的关联**

+   FL-PM-07 退回待入库成功后，系统自动跳转至本流程的编辑页面。
+   在 FL-PM-07 触发的编辑模式下，页面仅显示两个操作按钮：
    -   **取消**：放弃本次编辑，制度维持"待入库"状态（已对普通用户不可见）
    -   **再入库**：调用 FL-PM-01.3 提交入库，制度重新进入"已入库"状态
+   该约束强制退回操作形成快速修订闭环（临时修订，不允许长期滞留待入库）。

### 3.8 新增 §3.X FL-PM-07 退回待入库

在 FL-PM-06 章节之后新增 FL-PM-07 章节：

---

**§3.X FL-PM-07 退回待入库**

**§3.X.1 流程概述**

+   **流程目标**：制度管理员将一条"已入库"制度临时退回"待入库"状态，进行快速修订（修正录入或解析错误），修订完成后立即重新入库。
+   **触发条件**：UR-10 制度管理员在制度清单中选中一条"已入库"制度，发起"退回待入库"操作。
+   **操作角色**：UR-10 制度管理员（不含 UR-03 制度编写者）。
+   **设计定位**：仅用于临时快速修订（如导入录入错误、解析错误），不适用于制度内容实质变更（后者走运营生命周期 P2+）。退回后制度对普通用户立即不可见，强制快速完成修订闭环。
+   **结束条件**：退回成功，制度状态变为"待入库"，系统跳转至 FL-PM-03 待入库编辑页面。

**§3.X.2 流程步骤**

| 步骤号 | 步骤名称 | 执行者 | 输入 | 输出 |
| ------ | -------- | ------ | ---- | ---- |
| 1 | 发起退回 | UR-10 | policyId | - |
| 2 | 强制填写退回原因 | UR-10 | 退回原因（文本，必填） | - |
| 3 | 警示确认 | 系统 | - | 显示警示："该制度退回后将立即对普通用户不可见，请确认已告知相关人员或完成必要沟通" |
| 4 | 状态变更 | PolicyDomainService | policyId、退回原因 | 制度状态：已入库→待入库；退回原因已记录 |
| 5 | 跳转编辑页 | 系统 | policyId | 自动跳转至 FL-PM-03 待入库编辑页面，仅显示[取消]和[再入库]两个操作 |

**§3.X.3 UX 行为约束**

+   步骤5跳转后，编辑页面处于"退回修订模式"，仅提供两个操作：
    -   **取消**：放弃编辑，退出修订模式，制度维持"待入库"状态（普通用户仍不可见）
    -   **再入库**：调用 FL-PM-01.3 提交入库，制度重新变为"已入库"（普通用户可见恢复）
+   退回修订模式下隐藏其他功能入口，防止制度长期滞留待入库。

**§3.X.4 异常处理**

| 异常场景 | 处理策略 |
| -------- | -------- |
| 制度非"已入库"状态 | 拒绝操作，提示当前状态不支持退回 |
| 退回原因为空 | 前端校验拦截，不允许提交 |
| 并发操作冲突 | 乐观锁检测，返回冲突提示，刷新后重试 |
